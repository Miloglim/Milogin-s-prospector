# R1 全局登录与开发调试交付

日期：2026-10-11；工作区版本 0.15.0-alpha.1。用户批准按节点推进，本节点没有发布、合并或提交，没有新增依赖；现有测试账号保留，不进行复杂账号迁移或生产库修改。

## 已落地的范围

- 全局身份协调器：启动恢复、产品登录、记住登录、退出、会话失效、离线状态；登录或首次改密完成前不挂业务路由。产品账号与业务邮箱分开，原SMTP向导改为登录后显式打开。
- 主进程续期：Bearer仅内存，refresh通过safeStorage保存至userData/prospector-refresh.enc，绑定中心地址和稳定userId。正常退出保留记住登录，显式退出清理；不同用户的迟到网络/存储结果不得清理新账号。
- 服务端007增量迁移：只存续期令牌摘要，绑定已有稳定session_id，轮换访问/续期令牌。7天闲置、30天绝对期限；现有session_ttl_seconds仍控制访问会话默认一小时。并发续期只有一个成功，消费后的旧续期令牌401，不杀死已成功轮换的会话。管理员撤销、停用、安全版本变更、改密均阻断续期。
- 桌面首次改密：受限身份只能读取自身状态、改密和退出；不能访问CRM。表单确认密码仅前端校验，传输只含当前/新密码；改密撤销旧会话后重新登录。
- 旧本地资料保护：默认旧profile不打开DB、不运行迁移、不启动旧收发/Agent/备份。明确新建的开发profile才绑定一个中心地址+用户，重新登录同用户可用，另一用户不能读取。绑定元数据不含密钥。正式旧资料接中心属于R2。
- 开发底座：DEV界面预览只有合成数据、样例/空/错误/断线和角色导航；不能调用真实写入。dev:dual共享一个Vite开发服务器，启动运营/销售独立目录与真实测试登录，不反复输入账号，也不并发编译两套相同主进程文件。

## 如何验收

在项目目录启动测试中心，再启动双窗口：

```powershell
npm run crm:online:start
npm run dev:dual
```

1. 两个窗口分别进入测试运营和测试销售，左下账号菜单查看账号；在线协作页面无需再登录。此节点保留M2业务入口，最终运营导航/消息中心整合属于R3。
2. 开发界面预览切换角色、样例/空/错误/断线；确认真实账号不改变，写入按钮不可用。这个预览验证布局，不代替真实账号权限测试。
3. 记住登录后通过托盘退出/正常退出程序，再用同一profile重启，应恢复原用户；显式退出后应回登录，不能因开发自动登录再次进入。自动登录仅对首次未绑定的新目录执行。
4. 首次改密的测试身份进入改密页，不能打开CRM；新密码至少12个字符，完成后重新登录。不要为测试重复初始化或覆盖实际管理员密码。
5. 默认旧目录的客户/邮箱等入口显示尚未绑定提示，不读取或上传旧资料；这是R1保护行为。R2完成前不能据此验收个人CRM在线化。

开发脚本使用受控本机55844测试中心、55845开发渲染服务；如果端口冲突，明确失败，不改连别的中心。自动登录需匹配测试配置、运行instanceId和本机夹具；夹具密码不显示、不进入渲染代码。两端开发目录固定为.work/desktop-dual/operations与sales，停止命令保留目录，重复dev:dual会复用加密登录态；其变化不触发Vite全页重载。中心身份凭据请手动配置，不在Agent对话、源码或普通检查点保存。

## IPC/API 核查

| 桌面通道 | 服务端链路 | 说明 |
|---|---|---|
| online:login（沿用） | POST /api/auth/desktop/login，再读desktop/me | 唯一实际产品登录入口；不返回凭据给renderer |
| online:restore（新增） | desktop/refresh | 系统加密恢复，无密码保存 |
| online:status（新增） | desktop/me，必要时desktop/refresh | 全局身份健康检查，含本地可用状态 |
| online:password（新增） | POST /api/auth/desktop/password | 严格两个字段，改密后重新登录 |
| online:logout（沿用） | POST /api/auth/desktop/logout | 清本地凭据；有界等待中心撤销后通知重启 |
| 既有10个CRM通道 | 既有CRM API | 继续使用同一个主进程身份，不新增平行身份缓存 |

ONLINE常量、IPC.ONLINE与preload白名单共用一个来源。十五个通道有十五个处理器，注册测试拒绝缺失/重复；新增三个通道都有实际调用方。五个desktop认证端点分别承担登录/续期/退出/状态/改密；旧API与管理Cookie链路保留给现有调用方，不是桌面第二登录路径。

本地IPC占位拒绝和后续真实处理器均在transport/desktop-local.ipc.ts注册；替换时先移除占位，再同步注册受身份守卫保护的处理器，没有新增架构例外。身份失效先使主进程授权真源为空，个人IPC立即拒绝；已启用本地任务的开发窗口在有界退出处理后重启，终止所有旧任务。临时网络错误不伪造注销或本地写成功。

生产App不再展示页内登录，孤立OnlineWorkspace测试仍有无Provider兼容分支，仅验证旧M2页面；不能把这个测试入口作为正式产品路由。R2/R3仍需逐一迁移旧客户/看板/邮件调用方，再移除已无调用方的协议，禁止提前删接口造成空壳。

## 已知限制与下一节点

- 创建账号/恢复账号入口真实说明“尚未开放”。正式验证邮件通道尚未建立，本轮没有实现可验收的自助注册或密码恢复，不用测试激活链接冒充邮件验证。这是R1账号入口剩余项。
- 中心连接仍仅本机loopback；跨设备、HTTPS、公网部署不在本节点。
- 新开发目录可以测试个人本地功能；默认旧库保持保护，不猜历史归属。角色完整页面、定向分发与销售画像未在R1落地。
- 本地运行模块启用后切换身份采用重启边界，未保存草稿可能丢失。原任务没有完整stop-all端口；后续迁移Worker时再完善热切换。
- 退出立即阻止新个人IPC与旧响应；已执行的SMTP/IMAP/模型任务可能持续至中心退出完成或10秒请求超时后进程退出，不宣称取消已有外部效果。
- 续期响应在网络中丢失或写盘失败时可能需要重新登录；不盲重放已消费令牌。当前不实现短时间重复刷新回执缓存。
- 生产预览关闭按renderer生产构建验证；未制作/发布安装包。包体大小提示仍存在，未做多人容量或完整生产安全认证。
