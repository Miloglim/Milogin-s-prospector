# 团队成员协作与收件箱管理重构设计

日期：2026-11-06

## 1. 目标

团队“我的团队”主界面从只读监控升级为成员协作工作区；收件箱增加经典邮件软件式左侧管理栏，让邮件分组、标签、待办、分级和置顶成为长期可用的信息结构。

本设计坚持三条边界：

1. 成员邮件和联系人权限仍以中心现有授权为准，协作消息不能扩大原数据权限。
2. 不把聊天、运价确认和邮件标签做成仅前端存在的假状态。
3. 聊天、邮件引用、关注申请和运价确认都必须可追溯、幂等、可补偿。

## 2. 团队工作区

### 2.1 页面结构

保持现有三栏：

| 区域 | 内容 |
| --- | --- |
| 左栏 | 团队结构、常驻团队成员列表，当前账号不显示 |
| 中栏 | 与左栏选中成员的协作工作区，以聊天时间线为主 |
| 右栏 | 成员数据概览、待处理项和最近活动 |

中栏顶部显示成员身份；底部为固定输入框。原“团队动态”抽屉保留，作为聊天时间线的一段系统事件流，不再单独占据主视觉。

### 2.2 协作消息类型

| 类型 | 用途 | 必要状态 |
| --- | --- | --- |
| 文本消息 | 日常沟通、行动说明 | 发送中、已发送、已读 |
| 邮件引用 | 把一封有权限的邮件带入对话 | 引用有效、引用已失效 |
| 关注申请 | 请求主管或成员关注某联系人/任务 | 待处理、已接受、已拒绝、已过期 |
| 运价确认 | 成员提交运价，主管确认是否可用 | 待确认、通过、驳回、已撤回 |
| 系统事件 | 分配、接受、状态变化等自动记录 | 只读 |

邮件引用只保存稳定引用，不复制正文。打开时重新校验当前账号是否有权查看原邮件；无权限时显示“引用不可访问”，不能泄露标题和摘要。

### 2.3 运价确认卡

成员把 Navigator 运价带入聊天后生成确认卡：

- 线路、船司、柜型、价格、有效期、来源
- 发起人、指定确认主管
- 主管备注
- 状态和版本

只有目标主管、其上级管理员或超级管理员可以确认/驳回。发起人可撤回未处理请求。通过不等于直接对外发送报价，仍需进入原有发送流程。

### 2.4 权限

- 团队频道：当前团队成员、直属主管、管理员可见。
- 一对一会话：只对参与者可见；主管查看成员邮件的能力不自动扩大为查看私聊。
- 邮件引用：对话可见不等于原邮件可见，打开时再次校验。
- 运价确认：仅请求目标主管及其授权上级可处理。
- 所有消息和决策写审计事件，不使用删除物理清除历史。

## 3. 收件箱管理侧栏

### 3.1 布局

收件箱改为三栏：

| 区域 | 建议宽度 | 内容 |
| --- | --- | --- |
| 管理栏 | 200–220px | 快捷视图、联系人分组、标签、待办、分级、置顶 |
| 邮件列表 | 340–420px | 现有虚拟滚动邮件列表 |
| 邮件详情 | 自适应 | 正文、匹配联系人和 AI 分析 |

窗口较窄时可收起管理栏为图标栏；不得挤压正文到不可读宽度。

### 3.2 管理栏分区

1. 快捷视图：全部、未读、待处理、已收到、退信、已发送。
2. 联系人分组：已匹配客户公司、未匹配发件人、联系标签分组。
3. 我的标签：询价、报价、订单、投诉等用户标签，可新增、改名、设色。
4. 待办：今天、逾期、稍后；点击后只显示关联邮件。
5. 分级：紧急、重要、普通。
6. 置顶：独立置顶区，邮件可随时置顶/取消。

各分区可折叠；搜索和筛选条件组合后仍由同一查询端口计算，不能只在当前页过滤。

### 3.3 可立即复用与必须新增

可复用：

- 邮件分类、意图、匹配联系人、联系人标签
- AI 任务建议
- 现有联系人、任务和中心联系人引用
- 现有虚拟滚动与正文缓存

必须新增持久化：

- 邮件标签
- 邮件优先级
- 邮件置顶状态
- 邮件与任务的稳定来源关联
- 团队会话、消息、关注申请、运价确认

## 4. 数据契约

| priority | text | normal / important / urgent |
| archived_at | text nullable | 归档时间 |
| snoozed_until | text nullable | 稍后提醒 |
| version | integer | 乐观锁 |
| updated_at | text | 更新时间 |

`inbox_labels`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| label_id | text PK | UUID |
| account_id | integer | 账号隔离 |
| name | text | 标签名 |
| color | text | 颜色 |
| sort_order | integer | 排序 |

`inbox_mail_labels`

所有写操作必须携带 `idempotencyKey`，并写 outbox 事件和审计记录。

## 5. 状态流转

关注申请：`pending -> accepted | rejected | expired | cancelled`。

运价确认：`pending -> approved | rejected | cancelled | expired`，终态不可回退；重新确认必须新建请求。

聊天消息：发送成功后不可修改正文；撤回只写 `deleted_at` 并保留审计。

邮件标签/置顶/分级：普通可逆更新，使用版本避免多窗口覆盖。

## 6. 异常与补偿

- 消息发送超时：保留相同 `client_key`，重试只返回同一消息。
- 邮件引用失效：消息仍可见，引用区显示不可访问，不删除聊天记录。
- 运价确认目标主管失效：请求自动转给团队当前主负责人并通知。
- 标签删除：历史关系保留，列表查询过滤软删除标签。
- 本地库写入失败：UI 回滚乐观变化，并记录可重试操作。
- 团队解散或成员离队：会话只读，不再创建新消息；历史按权限保留。

## 7. 实施顺序

1. 契约评审：确认隐私边界、会话模型、邮件元数据和运价确认状态机。
2. 收件箱本地迁移：标签、置顶、分级、归档和任务关联。
3. 收件箱侧栏：先接可派生视图，再接新增元数据。
4. 团队协作后端：线程、消息、关注申请、运价确认和 outbox。
5. 团队协作前端：替换中栏成员详情为聊天工作区，保留右栏概览。
6. 测试与灰度：权限负向、幂等、并发、引用失效、主管变更和离线重试。

## 8. 不可接受的做法

- 前端本地假聊天，重启后消息消失。
- 把主管查看成员邮件自动扩展为查看私聊。
- 邮件引用直接复制正文，绕过原邮件权限。
- 运价确认通过后自动对外发信。
- 用前端当前页过滤冒充收件箱全局标签/待办筛选。
