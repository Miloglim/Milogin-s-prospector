## 原上线方案与协作边界（已由下方局域网方案取代）

1. 跨机器登录必须有双方信任的 HTTPS。当前局域网 HTTP 配置不能用于新授权链路；Navigator 原生 TLS 支持证书/私钥文件配置。不得关闭证书校验或临时信任任意代理头。
2. 服务端先更新，确认数据库初始化与接口，再更新 Prospector 和 `rates.url`。证书、私钥与配置在机器上手动配置，不能粘贴进 Agent 对话。当前没有发布、重启正式服务或修改另一台机器。
3. 新 `rates:status` 返回授权状态，`rates:sync` 退役。这是内部 IPC 行为变更，旧调用方需同步升级；本次没有发版，正式发布须按破坏性契约变更选择 major 版本并更新版本记录。
4. 两台开发机不要同时在同一个共享分支上直接修改后强推。每台用独立分支提交，再合并到共同分支；另一台继续前先提交或暂存自己的修改，再拉取并解决冲突。不能用拉取覆盖尚未保存的本地工作。

完整授权与 HTTP 契约在 Navigator 的 `docs/prospector-user-query-contract.md`；客户端现行来源规范见 [rates-remote-source-spec.md](rates-remote-source-spec.md)。生产 HTTPS 部署与实际运行效果需在完成切换后另行验收。
