# R3 定向分配与全局消息

2026-10-12，用户批准执行；工作区版本 0.18.0-alpha.1，未提交、推送或发布。

## 范围与数据流

运营客户详情 → 分配客户 → 选择负责销售及可选额外通知人 → online:assign → POST /api/crm/leads/:id/assign → 中心授权与版本校验 → 同事务客户归属、分配历史、管理审计、幂等回执和 outbox → 持久用户消息 → 销售消息中心 → 当前权限重查详情 → 精确打开客户。

销售手工跟进继续使用原 online:followup 和中心 PG 活动；有权来源运营在客户详情和消息中心看到反馈。没有另建 CRM 库或页面私有登录态。

首期只能分配本人运营来源、尚未分配的草稿或公共池客户。自有客户不自动转成运营来源，已分配客户不提供回收／转派。运营失去执行负责人资格后只看当前有权跟进，不再同时编辑或开发该客户。最高身份管理员仍需明确 CRM 准入及能力；默认 CRM admin 新增 leads.assign，不扩展已有显式能力子集，也不赋予其他运营来源的分配权。

额外通知人不自动获得客户或邮件权限；无详情权限时只收到分配提醒，customerId 为空、version 为 0、canOpen=false，不出现客户名称／邮箱或打开客户按钮。停用、改密、CRM 撤权与能力范围缩小会重新校验通知和详情。

## 消息、接口与防漂移

唯一应用级 NotificationProvider 在任何主页面持续补收。原 OnlineWorkspace 在正式应用中移交 feed 消费，保留孤立测试回退，不能两个页面各维护消费游标。消息按稳定 delivery ID 合并；已读与扫描游标分别处理，迟到 feed 不撤销刚完成的已读。

保留 online:feed/read；feed 兼容可选 OnlineFeedRequest {reset?:boolean}，用于首次挂载、权限变化或手动刷新从中心重新核验历史。重置首个成功页替换旧缓存、保留同 ID 已读，后续页追加；省略的失权旧通知被移除。重置前的迟到响应不得推进新游标。权限缩小时清旧消息、请求世代隔离，通知点击先重读受权客户，成功后标为已读并导航 /customers?customerId=UUID。路由 onResolved 与 hashchange 同时覆盖内置导航和外部深链。

新增仅 online:assign 与 online:members；20 个 ONLINE 常量、注册处理器和 preload 白名单一一对应。成员目录 GET /api/crm/members 分页，只给有效分配操作者读取；负责销售必须为有效 sales 且有 leads.develop。公共契约为 server/core/leads.ts、notifications.ts，通过 shared 导出，所有返回统一 Result。

009-directed-assignment 只向现有 outbox 加 recipient_user_ids，不修改 001–008 校验和。分配通知只投递给事务记录的负责销售、分配操作者及显式通知人，不广播给其他销售。客户权限派生 canAssign，不持久化第二份授权结论。版本冲突、重复幂等、目标停用、失权重试都在中心核验；网络失败不回写 SQLite。

分配弹窗固定打开时版本，按完整请求生成稳定幂等键；轮询不替换提交版本，关闭／切账号后的迟到响应不重开详情。
