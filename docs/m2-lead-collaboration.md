## 使用与范围

中心沿用 `npm.cmd run crm:online:start/status/stop/test`，独立测试PG为127.0.0.1:55843，中心为127.0.0.1:55844。服务源码变化必须停止后重启，不能只构建就宣称运行进程已更新。

Prospector新增在线协作入口，账号与当前有效能力决定运营/销售视图。账号管理网页仍负责身份与产品准入，Navigator继续使用既有系统。首次管理员必须先在管理页面改密；本机测试账号的密码仅在本机受控文件查看，不能发到Agent对话。

运营将CSV/XLSX直接放入应用，映射来源客户编号、公司、邮箱及可选姓名/国家，预览并导入；逐行查看有效、重复、无效和受限冲突，显式发布有效草稿。销售从公共池领取档案，已领取未触达客户也出现在本人列表；共享跟进及阶段回传运营。

公司名称不作为自动归并键。一个来源下客户编号确定档案分组，同档案联系人共用负责人。冲突私有客户不泄漏详情，不自动公开旧个人客户。协作操作统一由中心写入，断网报错，不回写旧SQLite。

本节点先合成线索、同机独立身份验证；跨设备绑定/TLS、自动发信/收信/AI持续执行、任务回收转派、旧库迁移与公网部署不计入本节点完成标准。

## 架构和契约

`server/core/leads.ts`、`server/core/notifications.ts`为HTTP与数据契约来源；`src/main/contract.ts`登记桌面IPC，`src/shared/online-crm.ts`提供桌面类型。服务无IO，数据库/网络/系统加密留在adapter，transport只解码、路由及返回。

新增迁移保留001–004校验和；档案/联系人关联、来源批次/原行、归属历史、幂等回执及通知feed与现有CRM/identity同处隔离PG。不建立第二套联系人库。

发布、领取和共享跟进与outbox同事务；已提交事件由投递器生成去重用户流。每用户head锁分配提交序列，不能以全局outbox自增值当可靠游标。补收按当前权限过滤旧事件正文，并推进已扫描位置；设备游标与用户已读分开。

通知内容保持最小定位信息，点击后重新鉴权读取具体档案；对象失权或变化后不显示缓存详情。账号停用、强制改密、产品撤权及归属变化必须同时影响读取、写入、旧幂等回执及通知。
