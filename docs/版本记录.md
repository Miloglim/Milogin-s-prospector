# 版本记录

## 0.56.0-alpha.5 — 2026-10-22（管理账号创建与重置修复）

- 管理中心创建账号时由当前超级管理员设置初始密码；固定 `123456` 默认密码已删除，密码只保存在哈希中，首次登录仍强制修改。
- 一次性重置链接的密码设置接口在生产 HTTPS 管理中心可用，不再返回“仅用于本机测试”；15 分钟一次性、同源、限流、账号状态和邮箱一致性校验保持。
- 正式下载打包入口强制分别提供中心与 Navigator 的 HTTPS Origin，并通过临时部署资源构建；发布前读取 `resources/assets/center.json` 校验 `baseUrl` 与 `ratesUrl`，不再把开发用本机地址带进安装包。
- 正式包已支持中心连接服务器、Navigator 连接独立 HTTPS 入口的混合部署；本次 Windows 包连接服务器中心与阿里云反向隧道下的本机 Navigator。

## 0.56.0-alpha.4 — 2026-10-22（联系人核心链路审计加固）

- 工作簿导入补齐软删除恢复：已映射或同邮箱软删除联系人会恢复原记录、保留原来源和历史、递增版本并写更新事件；无权限时仍拒绝且不产生公司/客户副作用。
- 客户级编辑只校验活动联系人，不再被软删除记录阻止；看板按联系人邮箱搜索也会排除已删除记录。
- 联系人镜像的增量游标只在当前格式且权限范围一致时有效。旧格式强制丢弃游标并重新完整同步，修复“本地已有数据但永远未就绪”的状态机矛盾。
- 收件箱联系人查询失败明确显示错误，不再伪装成“未提取”；已分配/无删除权限的联系人不显示删除入口。已有当日备份时不再重复执行并报失败。
- 收件箱退信详情优先显示中心镜像中已确认的退信联系人，旧 SQLite 关联仅作非中心模式回退，避免中心模式“已关联但详情不显示”。
- 联系人详情“在CRM中查看”改为携带 `centerContact + centerCustomer` 的看板深链，避免只打开看板却无法定位当前联系人。
- 发信成功后对 campaign 服务的动态导入收敛为统一异步通知函数；所有 sent/failed 回调都处理 Promise 拒绝，不再产生“任务未推进但发送已成功”的未处理异常。
- 修正自动回复/退信状态仍按未触达断言的过期测试；Vitest 默认并发限制为 4，消除全量 JSDOM 测试的无界资源争抢超时。
- 发送中心任务名改为可选；留空时按现有任务自动生成首个未占用的“任务N”，创建与草稿编辑共用同一规则并返回最终名称。
- 客户详情“往来记录”恢复旧版互动时间线样式：标题与条数、类型颜色、日期、标题和两行摘要；中心邮件、更正审计及普通跟进继续合并展示。

## 0.56.0-alpha.3 — 2026-10-22（收件箱删除与重加闭环）

- 联系人导入查重区分活动与软删除记录。已删除邮箱不再返回“联系人已存在”；同账号且仍有原客户删除权限时恢复原联系人和历史，版本递增并写联系人更新 outbox。无权限或归属冲突时明确返回受限冲突，且不创建猜测公司或空客户。
- 收件箱中的中心联系人删除入口接入现有多联系人删除契约，不再显示“暂未开放”；删除成功后立即刷新匹配。联系人新增成功后自动返回原邮件，匹配列表重新读取该联系人。
- 新增失败后的终态回执不再复用旧幂等键，避免联系人状态变化后反复拿到缓存的“已存在”结果。匹配栏同时识别收件人/抄送中已在库的联系人，但不会把未知内部地址变成添加提示，也不重复显示发件人。
- 中心写操作后匹配强制读取一次中心实时数据，直到完整镜像基线重新落地，避免本地旧镜像在删除或恢复后覆盖最新结果。

- 新增纯读取服务 `contact-match-reader.service.ts`，负责完整分页、账号切换检查和列表变化冲突；不新增 IPC、数据库迁移、依赖或持久化字段。

## 0.56.0-alpha.1 — 2026-10-22（联系状态与收件箱分类统一）

- 联系人联系状态统一为未触达、已触达、已回复、退信、自动回复；收件箱回复、退信和自动回复分类直接写同一个中心状态，详情和收件箱都可通过同一跟进接口人工修正，为后续 AI 识别打标保留同一写入口。
