# 本地发信与中心断线边界

## 问题

发送服务此前把中心连接状态当成所有发信任务的总开关。中心不可用时，销售自有线索的本地 SMTP 队列也无法创建、恢复或继续发送，与本地优先方案冲突。

## 实施

- 自有线索和本地测试邮件不再受中心连接状态阻断。
- 已保存的本地发送队列在中心断线时可以恢复并继续走本机 SMTP。
- 分配线索仍要求中心在线；创建、授权、发送前校验和回执上传规则不变。
- 中心线索在发送流中等待中心恢复，不阻塞其他本地发送流。
- 本地发送成功后仍写入本地收件箱、交互记录和联系人阶段；中心恢复后由既有邮件事件队列上传必要事实。

## 影响

中心离线时，销售可以继续处理自有线索和本地邮件任务；分配线索的权限、归属和发送回执仍以中心为准。没有新增数据库、IPC、HTTP 路由、依赖或配置。

## 验证

- `tests/unit/send-auto-resume.test.ts`：6 项通过，覆盖中心断线后本地队列恢复与本地 SMTP 发送。
- `tests/unit/center-send-runtime.test.ts`：9 项通过，中心发送授权与回执规则保持通过。
- `npm run typecheck`：通过。
- `npm run check`：扫描 233 个源码文件，通过。

本节点没有真实外发邮件，没有写入正式中心库。
