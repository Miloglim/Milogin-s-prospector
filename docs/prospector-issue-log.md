# Prospector 问题与修复摘要

## 2026-11-02 客户端 0.70.1 连接旧正式中心

- 现象：admin 删除联系人提示“资料参数无效”，团队页提示“CRM接口不存在”。
- 根因：已安装客户端是 0.70.1，但正式中心 `crm.47.96.159.26.sslip.io` 仍是旧版本；`/api/crm/team-context` 实测返回 404。删除联系人适配器此前又不会先校验中心引用，缺失中心编号或版本的旧记录会被服务端统一报成“资料操作参数无效”。
- 修改：客户端 0.70.2 在删除前校验 `customerId`、联系人版本和重复选择；不完整引用直接提示“联系人缺少中心编号或版本，请刷新后重试”，不发送无效请求。
- 验证：删除适配器与收件箱删除定向 25 项、typecheck、Electron build 通过。
- 边界：正式中心升级尚未执行，因此团队功能仍不可用；新版客户端尚未打包发布。

这是一份持续更新的问题台账，用来说明“发现了什么问题、真正原因是什么、最后怎么改、验证到什么程度”。技术细节、迁移和完整测试证据仍以对应交付文档、源码和测试为准；本页只保留能给人和后续 Agent 快速复盘的短摘要。

- 每个已确认并修改的功能问题，在完成后追加一条；只记录可定位的行为变化，不记录临时调试和纯样式微调。

## 2026-11-02 消息中心空状态居中

### 暂无消息图样贴在消息列表顶部

- 现象：消息中心没有消息时，空状态图样从正文区顶部开始排列，没有落在可见区域的中心。
- 原因：空状态放在消息滚动列表内，沿用了普通消息行的顶部布局，没有针对无数据状态设置居中容器。
- 修改：仅在消息数为零时让正文区切换到居中布局并取消空列表的滚动条沟槽；有消息时继续使用原列表布局。
- 验证：已修改、已测试、已现场验证；消息中心定向测试 31 项、typecheck 和 Electron build 通过。真实 Electron 1366×768 中空状态横纵偏移均为 0px，页面错误 0。
- 边界：未发布安装包；侧栏弹层和独立消息页共用同一面板组件，本次现场截图核对独立消息页布局。

## 2026-10-31 自动开发客户 B 测前闭环审计

### 首页推荐与正式发送身份源不一致

- 现象：中心账号下，首页「自动开发信」可能推荐旧本地联系人；名单进入任务后，发送向导和实际发送却要求中心联系人引用，存在推荐为空、错人或按旧库建任务的风险。
- 原因：推荐服务直接查询旧 `contacts` 表；中心正式选人、发送授权和回执使用授权联系人镜像与 `centerReference`，两套编号和事实源不一致。
- 修改：中心账号存在时，推荐统一读取中心发送端口的授权联系人快照和发送台账；名单交接同时携带中心联系人引用。中心联系人尚未同步时明确失败，不静默回退旧库；无中心会话的历史本地模式继续兼容。任务选人表也统一按“可发信”权限过滤，不再把可跟进和可发信混成一个权限。
- 验证：新增中心推荐、失败不回退和发信选人权限测试；自动开发、任务、中心发送定向 120 项通过。
- 边界：推荐仍只从当前账号已授权且可发送的联系人中产生，不会代替外部找客或导入；中心未完成首次联系人同步时不会给出旧库名单。

### 任务完成后回复和退信没有进入结果台账

- 现象：客户在最后一轮发出后才回复或退信，任务卡片仍显示“已完成”，`replied/bounced` 数量偏低，B 测看到的开发效果不完整。
- 原因：联系人信号止损只更新 `pending/queued`，把计划走完的 `sent` 终态排除在外。
- 修改：回复、退信信号可把计划已走完的 `sent` 触点改为 `replied` 或 `bounced`，保留已发轮次与发送时间；自动回复仍只顺延未发触点，不算任务回复。
- 验证：新增“计划结束后才回复/退信”的台账测试；任务与止损定向测试通过。
- 边界：信号来自已同步的收件箱分类；邮件尚未同步到应用时，任务台账不会提前变化。

### 发信账号全部不可用时中心任务延迟重排

- 现象：全部发信账号熔断或停用后，中心开发任务的剩余触点可能保持“已入队”，要等约 24 小时对账才回到待发。
- 原因：无健康账号的批量摘除分支只按旧本地联系人回调失败，没有携带中心联系人引用和任务编号。
- 修改：中心任务在该分支按原引用和 `campaignId` 回退到待发；旧本地任务保持原逻辑。
- 验证：中心发送与任务定向测试通过。
- 边界：账号恢复后由任务扫描器重新排期；不会静默换用其他未授权账号。

### 客户分级残缺响应会让详情页崩溃

- 现象：B 测前完整回归并发运行时，客户详情收到缺少有效等级的分级载荷后整块渲染中断。
- 原因：组件只用 `item` 是否存在判断，直接对空的 `effectiveGrade` 调用字符串方法。
- 修改：有效等级缺失时显示占位，不再继续渲染依赖等级明细的区块；隔离复现连续通过。
- 边界：这是前端容错，不改变服务端分级契约，也不把残缺数据伪装成 A/B/C。

### B 测结论

- 已完成：`0.70.1` 工作区、类型检查、Electron 构建、架构检查 5 项、完整 Vitest 254 文件/1,919 项通过、213 项按环境跳过；本机 55847 `/health/ready` 返回 200，Mock 数据状态可读。
- 未完成：未用真实登录账号完成 `首页推荐 → 建任务 → 启动 → 收件箱回复止损` 的桌面点击路径；未发送真实邮件、未连接真实邮箱、未部署正式中心、未生成安装包。
- 环境阻碍：当前 55847 进程健康，但缺少受控生命周期进程记录，`crm:online:status` 拒绝确认；下次 B 测前应先干净重启中心并用生命周期脚本启动。当前 Electron 主进程启动时间早于 `0.70.1`，也必须从托盘重启加载新主进程。
- B 测要求：桌面应用需保持运行（可最小化到托盘），中心需在线且至少一个健康发信账号；应用完全退出或中心断线时不会在后台继续自动发送，重连后需用户明确恢复任务。

## 2026-10-30 团队只能创建和加入，不能解散

### 组织关系没有生命周期，删除会破坏联系人和历史审计

- 现象：团队页只有创建、邀请、移动和成员调整，没有负责人或管理员的解散入口；只能建不能收口。
- 原因：canonical 组织单元和成员关系都按活动记录建模，没有软解散字段、审计、活动关系过滤和幂等路由。
- 修改：新增 064 软解散迁移；primary leader、运营管理员和超级管理员可解散叶子组织，公司根和有活动下级的运营组拒绝。解散只结束组织关系、取消 pending 邀请、删除展示分组并写审计，联系人、当前归属、分配和来源组织快照不变。团队上下文、分配主管、监督、监控和绩效统一只读取活动关系。
- 验证：typecheck、组织规则/HTTP/团队渲染定向测试、隔离 PostgreSQL 12 项、完整 bootstrap 和 DMS 空库执行通过；完整 bootstrap 为 115 表、1119 字段、1306 约束、321 索引、46 条迁移。
- 边界：本机开发中心已应用 064 并重启，ready 200；未发布安装包，也未做真实 Electron 点击验收。`crm_org_dissolution_audits` 是历史事实，不提供恢复/重建已解散团队的产品入口。

## 2026-10-30 已有邮箱首次上线邮件不全

### 首次同步只看短期水位导致存量邮件不完整

- 现象：已有邮箱用户迁移到 Prospector 后，收件箱可能只出现近期少量邮件；进度只显示当前批次，看起来像固定节点，用户也不知道还要拉多少。
- 原因：常规增量主要依赖近期时间窗口和本地不足 200 封时的补拉；没有账号级首次同步窗口与可恢复总量，超过 500 封时后续批次还要等下一轮定时任务。进度载荷也只有当前批次 `scanned/total`。
- 修改：新增本机 `email_sync_state`；首次同步按最近 90 天入站邮件与服务器最新 200 封并集计算，500 封一批并在同一后台任务连续跑完。首次完成后可继续补拉更早 1/3/6/12 个月；保存 IMAP 账号后立即首拉；老账号在新设备提示连接已有邮箱。
- 验证：typecheck、32 项邮件同步/刷新/布局/向导定向测试、19 项收件箱渲染测试、5 项应用布局/向导渲染测试、Electron build、架构检查 5 项、270 文件边界扫描及隔离 Electron 合成中心冒烟通过；冒烟确认真实收件箱路由、累计进度、当前主题和转入后台，页面错误 0。
- 边界：未连接真实邮箱、未操作正式中心、未发布安装包。POP3 仍受协议能力限制，只读取最新 40 个序号；真实大邮箱耗时与网络中断恢复仍需桌面现场验收。

## 2026-10-30 联系人分组切换时界面上下跳动

### 分类标签切换会清空列表并重新排高度

- 现象：在联系人分组的“导入批次 / 国家 / 公司 / 客户类型”之间切换时，左侧标题和列表反复上下移动。

- 修改：分类查询保留上一帧数据并降低透明度表示刷新；占位数据不参与默认分组选择；标题、标签、列表和分页各自使用固定 flex 轨道，分页槽始终保留高度。

- 边界：纯前端布局与查询状态调整，不修改接口、数据库或业务权限。

## 2026-10-30 主界面字体发虚

### 小字号与合成字重叠加导致文字不够清晰

- 现象：主界面文字整体看起来发虚，长时间阅读容易疲劳。
- 原因：界面大量使用 9–11px 小字，并混有 550/620/650 等 Windows 中文字体没有原生字形的中间字重，Chromium 会合成加粗；首轮切换到雅黑 UI 后清晰度提升，但反馈笔画偏尖锐。
- 修改：主界面最终改为 `Noto Sans SC` 优先的可变字体栈，正文基准 14px、小字 12px、表格与紧凑控件 13px；Segoe UI、雅黑 UI 仅作缺少 Noto 时的兜底。Ant Design 使用同一字体和字号 token；中间字重统一为标准 500/600/700，并禁用字体合成。
- 验证：typography/table/inbox 定向 10 项、联系人分组与收件箱渲染 22 项、typecheck、Electron build 和 270 文件架构检查通过；隔离 Electron 实际解析为 `Noto Sans SC 14px`，`font-synthesis:none`，页面错误 0。
- 边界：仅调整视觉排版，不改接口、数据和业务逻辑；极密集监控画布仍保留少量 10–11px 元信息，但改用标准字重避免合成模糊。

## 2026-10-29 当前功能迭代

### 团队组织模型与 canonical 真源

- 现象：团队页能创建和邀请，但组织关系仍依赖旧单层团队表；普通成员可能看到同事，负责人候选和成员总数与真实组织不一致。
- 原因：055 之前把运营节点、销售团队和成员关系混在旧 `crm_team*` 表；接口没有明确的公司根、运营组、叶子团队和 primary leader 规则。
- 修改：新增 canonical `crm_org_*` 模型和 055/056 迁移；运行时改为组织真源；补齐负责人、移动、成员、分组、过期邀请、候选和幂等读写闭环；部署 SQL 与 mock 脚本同步。
- 验证：隔离 PostgreSQL 11 项、组织/HTTP/渲染定向测试、typecheck、Electron build、架构检查和合成 Electron 1440/1040/824 三视口通过；页面错误 0。
- 边界：本机开发中心尚未执行 055/056 迁移并重启，旧进程的 mock 状态不能作为 canonical 验收；需在统一开发验收环境完成最后一步。

### 联系人分配缺少超时、转交和主管监督闭环

- 现象：分配请求只能接受/拒绝/撤回；没有超时、转交、归属历史，主管通过普通联系人权限查看下属客户，通知也打不开。
- 原因：旧表把 `pending/accepted` 当成全部生命周期，负责人直接由分配记录或客户负责人推断，通知和访问权限没有独立监督契约。
- 修改：新增 057 分配状态迁移、7 天到期、转交状态、ownership 历史、30 秒有界超时调度器和独立监督审计；主管通知只进入只读 monitor DTO，普通列表/详情不授予访问；退役的任意通知人入口固定返回冲突。
- 验证：隔离 PostgreSQL 15 项、分配状态/渲染/通知定向测试通过；typecheck、build、架构检查通过。界面已补过期/待转交标签、转交确认和监督详情。
- 边界：本机中心尚未执行 057 并重启；部署模板需随统一版本一起落地。

### 线索入口各自查重导致重复联系人

- 现象：平表、工作簿、手工新增、邮箱修改和 Agent/API 对同一客户可能给出不同重复结果，模糊公司有时直接绕过人工确认。
- 原因：各入口各自维护邮箱/公司判断，缺少统一事务网关和冲突裁决审计。
- 修改：新增 058 统一 LeadIngress 和 `crm_lead_match_decisions`，邮箱/域名/公司/模糊候选按固定优先级处理；所有写入入口复用同一网关，新增处理抽屉支持关联公司、新建和恢复软删除联系人的幂等裁决。
- 验证：CP3 定向 17 项、隔离 PostgreSQL 28 项、typecheck、build、架构检查和 crm:pg:check 通过；平表/工作簿/手工编辑和隐私候选有渲染用例。
- 边界：058 尚未同步部署模板；本机旧中心不能做真实点击验收；工作簿入口需在主客户页进一步接入可见路由。

### 邮件分类没有可追溯的人工/AI 优先级

- 现象：邮件只能按现有机械分类展示，AI 晚到可能覆盖人工结论，无关邮件也可能被误当成客户动作。
- 原因：分析没有独立追加历史、人工锁和业务信号契约，分类与任务资格混在一起。
- 修改：新增 059 邮件分析追加表、规则/AI/人工来源、结构化信号、人工锁、晚到版本抑制和可选 AI 队列；中心只接收摘要和元数据，不接收正文/附件。收件箱、联系人时间线和监督详情已显示并支持人工修正。
- 验证：邮件分析定向 82 项、隔离 PostgreSQL 回环、typecheck、build、架构检查通过；人工优先、退信/自动回复/客户回复、无关邮件无待办和权限负向均有用例。
- 边界：059 尚未部署；AI 提供方未接入实际模型，队列默认可注入但关闭。

### 主管关注与待办混在一起

- 现象：邮件行动建议没有独立的团队关注项，主管无法把重要回复、报价超时或退信修正转给成员，成员也不清楚完成回传。
- 原因：任务只有负责人视角，没有目标成员、来源主管、原因、版本和处理结果状态。
- 修改：新增 060 团队关注项与审计/幂等，强规则可直接建议待办，关注项独立于客户任务；团队工作台和消息中心已接入关注深链。
- 验证：关注/任务定向 17 项、团队/通知渲染 22 项、隔离 PostgreSQL 通知回环 12 项通过；普通成员、直属主管和运营只读边界已验证。
- 边界：060 尚未部署；收件箱精确邮件定位和工作台像素截图需统一验收。
