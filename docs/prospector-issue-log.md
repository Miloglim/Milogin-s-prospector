# Prospector 问题与修复摘要

这是一份持续更新的问题台账，用来说明“发现了什么问题、真正原因是什么、最后怎么改、验证到什么程度”。技术细节、迁移和完整测试证据仍以对应交付文档、源码和测试为准；本页只保留能给人和后续 Agent 快速复盘的短摘要。

## 更新规则

- 每个已确认并修改的功能问题，在完成后追加一条；只记录可定位的行为变化，不记录临时调试和纯样式微调。
- 每条固定写：用户现象、真实原因、修改结果、验证情况、剩余边界。
- 状态必须区分“已修改 / 已测试 / 已现场验证 / 未发布”，不能把测试通过写成真实业务验收。
- 新问题优先写清受影响入口，不只写用户最先看到的那一个页面。

## 2026-10-26 当前轮问题

### 导入 5000 多条联系人后客户端整体变慢

- 现象：一次导入 5000 多条联系人后，客户端持续响应迟钝，客户页和后台操作都不够顺畅。
- 原因：联系人变化页虽然有增量游标，但每条联系人都会单独开启本地 SQLite 写入，并在写入前读取、解析整张联系人镜像；导入量越大，读取次数和工作量越接近平方级。跟进看板还每 5 秒分页读取全部联系人，再在渲染端过滤出已触达记录。
- 修改：同一变化页的 upsert 合并为一次批量写入；旧快照只查询本批 contactId。跟进看板改为直接查询 `followupOnly` 的四类联系人，不再拉取全部 5000 条。跨页全选的重复检查改为增量 Set。
- 验证：5000 行镜像更新测试、每页批量同步测试、联系人镜像/看板/端口定向测试 72 项通过，完整回归 1,748 项通过；typecheck、Electron build 和架构检查通过。本机实际镜像 5,176 条联系人均为未触达，旧全表读取单次约 46 ms，新看板查询为 0 条且约 0.01 ms。
- 边界：已安装的 `0.58.0` 客户端仍包含旧路径，需要构建并安装 `0.58.1` 后生效；已发送邮件全量读取仍是独立容量边界。

### 一键已读提示“接口不存在”

- 现象：客户端点击消息中心“全部已读”后显示接口不存在。
- 原因：正式云中心仍是旧部署，没有 `POST /api/crm/notifications/read-all`；同一路由在本机中心返回 401，正式中心返回 404，证明客户端和本机代码正常。
- 修改：客户端在批量接口返回 `NOT_FOUND` 时自动回退到已有单条已读接口，按 8 个并发处理当前未读消息；云中心升级后仍优先使用一次批量请求。
- 验证：兼容回退渲染测试覆盖批量 404、两条单条已读成功、角标和未读点归零；消息中心 15 项定向测试和 typecheck 通过。
- 边界：回退需要为每条未读消息发送一个请求，最多沿用消息中心当前加载的 500 条。正式云中心随后已部署批量路由，GitHub `v0.58.0` 稳定 Release 与下载页也已同步。

### 中心超级管理员登录 Navigator 后仍不是全功能视图

- 现象：中心身份管理员登录 Navigator 后，账号被识别为普通管理员，来源群、舱位、公告和运营归属等受限界面仍不可见。
- 原因：中心 `/api/navigator/access` 把 `identity_admin` 映射成 `admin`，Navigator 又只对 `admin`/`operator` 硬编码开放部分页面，前后端都没有正式的 `superadmin` 角色。
- 修改：中心产品准入改为返回 `superadmin`；Navigator 增加正式角色、数据库约束、视图与路由全集，并保持普通管理员不能授予或维护超级管理员。留言板仍遵守开发开关。
- 验证：中心 server build 与 typecheck 通过，本机 55847 已重建并重启，live/ready 正常；Navigator 89 项后端定向测试、JavaScript 语法与浏览器可见性测试通过，8795 健康且 PostgreSQL 正常。
- 边界：管理员专项集成测试因隔离 PostgreSQL 环境未启用而跳过；未使用真实管理员密码完成一次浏览器登录，需用户在已登录页面刷新后确认角色显示为“超级管理员”。

### 更新检查依赖 GitHub REST API 配额

- 现象：客户端检查新版本时可能受 GitHub 未认证 REST API 限流影响，或把发布源错误统一显示成仓库权限问题。
- 原因：主进程直接请求 GitHub Releases REST API，且旧版本比较只取版本核心段，不能可靠区分 `alpha.1`、`alpha.2`。
- 修改：改用公开 Release Atom；新增独立解析、SemVer 预发布比较与稳定/预发布通道选择。REST API 不再参与常规更新检测，下载仍使用 electron-updater 的 Release 资产。
- 验证：Atom 解析、通道选择、预发布比较和“源码不得包含 api.github.com”测试通过；真实 Electron 主进程读取公网 Atom 后，`update:listVersions` 返回 5 个版本，`update:check` 返回成功，不再出现 403。全量回归 `1740 passed / 187 skipped`。
- 边界：Release 必须继续包含当前版本 EXE、blockmap 和 `latest.yml`；Atom 只负责发现新版本，不替代下载资产校验。

### 程序长时间运行后响应变慢

- 现象：应用常驻较久后，页面操作和收件箱滚动可能逐渐不够顺畅。
- 原因：当前短时采样没有复现内存或句柄持续增长，但存在两个确定的后台成本：窗口隐藏后多组 5 秒轮询仍可能运行；收件箱虚拟滚动每次更新滚动位置都会重新筛选和聚合整份邮件数组。已发送邮件还保持不限量读取，数据越多成本越明显。
- 修改：身份、通知、客户列表、跟进任务和商机页统一改为可见页面才轮询，隐藏时暂停、恢复可见立即刷新，并阻止轮询重入；收件箱筛选、发件人聚合和退信排序按输入缓存，滚动不再执行整表筛选。
- 验证：可见轮询的隐藏暂停、恢复刷新和防重入测试通过；收件箱 19 项及相关客户/任务/商机渲染回归通过；类型检查通过。
- 边界：已发送邮件的服务端分页尚未改动，历史邮件继续全量返回；本次只能降低重复计算和隐藏窗口负载，不能证明所有长时变慢都已消除。仍需要用运行小时数和具体慢页面做长时实测。

## 2026-10-25 当前轮问题

### 未匹配的导入字段没有可查看的备注

- 现象：来源表包含会员年限、协会、公司简介、传真、邮箱验证结果等额外字段时，旧导入只把这些列留在原始行 JSON 中，联系人详情和搜索看不到。
- 原因：平面导入只保存明确映射到业务字段的值，未匹配列没有转换为联系人备注；手工逐文件加备注列无法覆盖后续导入。
- 修改：服务端按最终字段映射自动收集未匹配的非空列，以“字段名：内容”逐行写入 `contacts.extra.note`；联系人详情显示只读备注，联系人搜索和 CSV 导出包含备注。
- 验证：转换规则单测、详情渲染、联系人端口导出、隔离 PostgreSQL 写入与备注搜索通过；重复/超长边界和原有导入权限继续覆盖。
- 边界：备注作为只读导入证据，不提供独立编辑入口；单条超过 20,000 字符时该行失败，不截断或拆分成多个业务记录。正式中心与安装包尚未部署本轮代码。

### 开发端启动后显示中心不可达

- 现象：开发端打开后提示中心不可达，但配置仍指向预期地址 `http://127.0.0.1:55847`。
- 原因：Windows 在 2026-10-23 18:08 重启过；本机中心 PostgreSQL `55846` 与 HTTP `55847` 都没有开机自启动，而开发启动器在 2026-10-25 16:03 先启动，因此连接被拒绝。中心日志最后一次正常运行停在重启前。
- 修改：启动本机中心专用 PostgreSQL 和 production-server，两个监听恢复；未修改开发端地址或云端中心。
- 验证：`http://127.0.0.1:55847/health/ready` 返回 200，production-server 生命周期检查通过，55846/55847 均在监听。
- 边界：本机中心仍未注册为 Windows 自动服务；机器重启后需要重新启动本机中心，或由用户点击开发端左上角品牌执行“检查并重连中心”。真实桌面会自动重连还是需要手动触发，取决于当前是否仍保留可验证的离线会话。

### 导入联系人预览中的长字段把表格行撑高

- 现象：导入联系人进入预览后，公司名、职位、网站或来源字段内容较长时，单元格会换行并把整行撑高。
- 原因：预览表虽然声明了列宽，但仍使用自动表格布局；数据单元格没有单行、隐藏溢出和省略号规则，长文本可以改变实际布局。
- 修改：预览表改为固定列宽，所有数据列启用省略；单元格统一单行显示并保留鼠标悬浮查看完整值，字段映射、预览数据和导入请求不变。
- 验证：超长字段的隔离 Electron 真实点击链中，两行预览行高均保持 `42px`，单元格为 `nowrap`、溢出隐藏和省略号；6 项定向测试、typecheck、Electron build 通过，页面错误为 0。
- 边界：完整内容仍通过单元格 `title` 提示查看；本次只调整预览显示，不改变文件解析或导入结果。

## 2026-10-23 当前轮问题

### 管理中心增加只读数据库数据浏览

- 现象：管理中心此前只有用户、产品和运行概览，超级管理员无法直接核对中心业务表的真实记录。
- 原因：管理页面没有受控的表目录和数据页接口；直接接数据库或做任意 SQL 控制台又会扩大凭据、误写和越权风险。
- 修改：新增仅身份超级管理员可见的“数据浏览”，提供 15 个白名单业务表的搜索、排序和服务端分页；凭据、会话、刷新令牌、挑战、登录别名及导入原始行不提供浏览，页面没有写入入口。
- 验证：定向单元/API/渲染 21 项、隔离 PostgreSQL/HTTP 17 项、typecheck、管理中心和中心服务构建通过；真实本地页面已切换用户与联系人并检查窄视口。真实库测试发现并修复了带搜索时 `LIMIT/OFFSET` 参数倒置。
- 边界：这是新增能力，不是故障修复；仅 `0.57.0-alpha.2` 工作区/本地测试中心可用，正式中心尚未部署，安装包未发布。

### 消息中心在中心短暂离线后整块不可点击

- 现象：开发客户端重新启动后，侧栏“消息中心”变灰且无法打开；云端中心和最新消息功能本身均正常。
- 原因：开发启动器固定连接本机正式中心 `127.0.0.1:55847`，当时本机中心 PostgreSQL 与 HTTP 服务已停止，客户端进入离线工作区；侧栏原逻辑把离线时的整个消息入口禁用。
- 修改：恢复本机中心数据库和服务；消息中心入口改为离线也可打开当前会话已有的缓存消息，只禁用需要联网写入的“全部已读”，并在按钮上说明原因。
- 验证：本机中心 `/health/ready` 与生产中心生命周期检查通过；离线入口、在线批量已读等 27 项定向渲染测试通过，typecheck 通过。
- 边界：离线且应用刚重启时没有可恢复的内存消息，面板会显示连接错误或空状态；重新联网后可继续拉取。尚未重新打包安装版。

### 收件箱新增联系人后，公司页人数要再点一次才更新

- 现象：从收件箱未匹配邮箱新增联系人后切到公司页，新公司或公司人数不会立即更新，点击其他组件或等待轮询后才出现。
- 原因：联系人保存成功时虽然失效了 `center-companies`，但公司页此时已经卸载；React Query 默认只立即重拉激活中的查询，未激活的公司缓存只被标记过期，因此切回后先显示旧数据。
- 修改：联系人新增成功后，在保留原有多域失效的同时，主动补拉未激活的公司列表和公司详情缓存；查询键、中心接口和数据结构均未改变。
- 验证：新增定向渲染用例覆盖“先打开公司→联系人新增→立即切回公司并显示 1 人”；隔离 Electron 真实点击链在切换到公司前已重新请求公司列表，页面无错误。
- 边界：该修复随下一次客户端构建生效；当前运行中的旧客户端仍未加载此代码。

## 2026-10-22 当前轮问题

### 外部运价入口突然 502，但本机 8795 仍健康

- 现象：`https://rates-office…` 和 `https://rates…` 的 `/api/health/live` 返回 502，本机 `http://127.0.0.1:8795/api/health/live` 仍为 200。
- 原因：外部 HTTPS 由 `Milogin Navigator Office Tunnel` 计划任务通过 SSH 反向转发到本机 `8795`。任务在 09:59 因远端 `18795` 被旧连接占用而反复失败，随后任务退出；服务器端 `18795` 无监听，Caddy 只能返回 502。
- 修改：确认本机 8795、中心 55847 和服务器中心健康后，启动现有隧道任务；显式验证 `-R 127.0.0.1:18795:127.0.0.1:8795` 可建立，并为任务增加每分钟自检触发，仍保留同一实例互斥。
- 验证：服务器 `127.0.0.1:18795` 监听，两个 `rates-office`/`rates` 的 `/api/health/live` 均返回 200；任务状态 Running，下一次触发已排定。
- 边界：隧道依赖本机在线、Windows 登录会话和 SSH 出网；本机休眠/断网后仍会出现短暂 502，需由任务重连或唤醒机器。

### Navigator 改密写到了本地旧密码库

- 现象：用户在 Navigator 改密后，中心账号密码没有变化，存在本地旧哈希先变化的风险。
- 原因：Navigator 中心模式仍调用 `account_selfservice.change_password`，执行本地 `operators.password_hash` 更新。
- 修改：新增中心 `/api/account/password`，Navigator 使用普通中心 API 会话调用；成功后再删除本地会话和中心令牌，本地哈希保持不变。Prospector 继续走中心桌面会话端点。
- 验证：隔离 PostgreSQL/HTTP 16 项、Navigator 21 项测试和临时账号跨栈改密通过；旧 Cookie、中心旧密码都失效，新密码可登录。本机与云端服务健康。
- 边界：未用真实员工账号执行现场改密；员工首次点击仍需在真实浏览器验证错误提示与重新登录流程。

### 管理中心用户列表没有按权限排序

- 现象：用户管理中心只按创建时间显示，管理员、普通用户、审计员和未授权账号混在一起。
- 原因：`/admin-api/users` 的 SQL 直接按 `created_at DESC` 排序，没有使用统一身份显示优先级。
- 修改：在数据库分页前按“身份超级管理员 → 当前产品超级管理员 → 管理员 → 用户 → 审计员 → 未授权”排序，同权限再按创建时间倒序；产品筛选使用对应产品的有效授权。
- 验证：typecheck、服务端构建和隔离 PostgreSQL 8 项账号生命周期测试通过，新增排序用例覆盖六种权限顺序。
- 边界：列表仍会包含已停用但未删除账号；本次只调整权限顺序，不改变停用状态展示。

### 删除账号后同邮箱重新创建或自助注册提示“已注册”

- 现象：账号删除后，再用同一邮箱从管理中心创建或从 Navigator/Prospector 自助注册，会返回“该邮箱已注册”或“账号已存在”。
- 原因：账号删除采用软删除，`identity.login_emails.email` 唯一记录仍保留；创建和自助注册只判断邮箱是否存在，没有区分活动与归档身份。
- 修改：管理中心“删除”改名为“停用并归档”，新增“已归档”列表和 `user.restore` 显式恢复；恢复必须设置新初始密码。`user.create` 和自助注册遇到归档邮箱只提示联系管理员，不再静默复用旧身份。
- 验证：typecheck、管理端/服务端构建、隔离 PostgreSQL 9 项账号生命周期和 7 项真实 HTTP 注册测试通过，覆盖归档筛选、创建拒绝、显式恢复、旧会话撤销、新密码及产品授权保留。
- 边界：恢复仍复用原中心身份 ID，因此个人资料和成长历史属于同一身份；如邮箱会交给不同人员，后续需要独立硬删除/匿名化方案。

### 删除中心账号提示“管理请求无效”

- 现象：本机管理中心删除账号时，旧页面提交了空字符串删除原因，服务端把空原因当作非法命令，因此返回“管理请求无效”。
- 原因：删除原因虽然名义上可选，但只要字段存在就按非空字符串校验；页面又始终发送空值。删除同时被放进管理员密码重新认证分支，形成无必要的二次确认。
- 修改：删除改为一次明确确认，直接提交用户 ID 与版本号；不再要求重复邮箱、管理员密码或原因。服务端单独处理 `user.delete`，空原因按未填写处理，同时保留 CSRF、超级管理员、版本冲突、自删、最后管理员、线索归属和联系人分配保护。
- 验证：typecheck、管理端/服务端构建、删除相关 28 项单元测试和隔离 PostgreSQL 7 项回滚测试通过。
- 边界：未用真实账号执行永久删除；运行时使用一次确认后仍需遵守业务归属限制。

### 客户端提示“更新仓库未找到”

- 现象：安装版 `0.56.0-alpha.4` 检查更新时显示“更新仓库未找到”，但 GitHub 仓库公开可读。
- 原因：`v0.56.0-alpha.5` Release 只上传了 EXE 和 blockmap，漏传 electron-updater 必需的 `latest.yml`；客户端下载元数据得到 404，界面又统一把它翻译成仓库权限问题。
- 修改：补传 `latest.yml`；发布脚本改为强制校验当前版本 EXE、blockmap、`latest.yml` 和 SHA-512，Release 已存在时使用补传而不是重复建 Release。
- 验证：`latest.yml` 公网地址返回 200，版本、文件名、大小和 SHA-512 与安装包一致；GitHub 三个资产的 digest 已核对。
- 边界：当前运行中的客户端需重新点击“检查更新”或重启后再检查；尚未在另一台 Windows 电脑完成整包升级。

### 正式安装包误连本机中心，外部同事无法登录

- 现象：已发布安装包打开后请求 `http://127.0.0.1:55847`，没有连接正式中心服务器。
- 原因：正式下载脚本直接运行普通 `npm run pack`，打包资源仍使用开发用 `assets/center.json`。
- 修改：正式打包入口要求两个不同的 HTTPS Origin，调用部署构建生成临时资源，并在发布前强制核对构建产物的 `baseUrl` 与 `ratesUrl`。
- 验证：从干净提交构建 `0.56.0-alpha.5`；中心配置为服务器地址，Navigator 配置为独立 HTTPS 隧道地址；GitHub 预发布资产、两处下载清单、HEAD、完整 GET 与 SHA256 实测一致，隔离启动真实 Electron 无崩溃。
- 边界：安装包未签名；公司电脑真机安装和真实账号完整点击链仍需现场验收。

### 管理中心创建账号后无人知道密码，重置链接又提示仅限本机测试

- 现象：创建运营管理员时不要求设置密码，账号创建后无法登录；点击重置密码并提交新密码，又提示“一次性凭据仅用于本机测试”。
- 原因：创建服务固定写入 `123456` 且不回传；生产管理 HTTP 把一次性密码设置接口硬编码为只允许 `test_mode`。
- 修改：创建用户表单新增初始密码和确认输入，后端哈希管理员提供的密码并继续强制首次登录改密；生产环境开放同源、限流、15 分钟一次性的恢复链接消费。
- 验证：管理服务、HTTP 和渲染测试覆盖初始密码传递、缺失密码拒绝、生产环境挑战消费。
- 边界：中心服务已部署 `0.56.0-alpha.5`；真实运营账号的创建、初始登录和首次改密完整点击链仍需现场验收。

### 删除联系人后重新添加仍提示“已存在”

- 现象：联系人删除后，从收件箱未匹配邮箱添加，仍被提示已有联系人。
- 原因：邮箱唯一索引包含软删除记录，导入查重没有区分是否已删除；前端终态失败后还复用了旧幂等键。
- 修改：同邮箱软删除记录在权限和客户归属允许时恢复原联系人，保留历史、来源和客户，版本递增并写更新事件；终态回执结束本轮幂等请求。
- 验证：隔离 PostgreSQL、真实中心事务回滚、联系人/收件箱定向测试通过。
- 边界：真实登录窗口的完整点击链仍需现场确认。

### 收件箱把已有联系人显示为未匹配

- 现象：邮件发件人和正文联系人在中心库中存在，但匹配栏显示未匹配。
- 原因：本地镜像未就绪时直接返回空数组；旧镜像升级后仍沿用失效增量游标，长期无法进入 ready 状态。
- 修改：镜像不可用时回退中心实时联系人；旧格式游标自动失效并执行完整基线；CRM 写后保持新鲜读取直到完整镜像重建。
- 验证：匹配分页、镜像格式和中途失败测试通过；真实窗口登录后的 v2 晋升仍待确认。

### 删除联系人后客户编辑和看板搜索仍受旧记录影响

- 现象：联系人已经删除，客户编辑仍要求保留旧联系人，按旧邮箱搜索也还能命中客户。
- 原因：两个兄弟查询没有过滤 `crm_deleted_at`。
- 修改：客户编辑、看板搜索和工作簿导入统一只把活动联系人作为当前关系；软删除邮箱仍走恢复入口。
- 验证：隔离 PostgreSQL 生命周期和工作簿测试通过。

### 工作簿导入与普通导入行为不一致

- 现象：普通新增已能恢复软删除联系人，但工作簿导入仍可能报重复。
- 原因：两条导入链路各自实现查重，只修了其中一条。
- 修改：工作簿导入补齐恢复逻辑，并保留原 `source/source_detail` 和历史。
- 验证：工作簿 PostgreSQL 恢复测试通过。

### 收件箱退信详情看不到中心联系人

- 现象：中心已经记录退信关联，详情仍可能没有“被退联系人”。
- 原因：详情只查旧 SQLite 关联，忽略中心镜像邮件链接。
- 修改：中心模式优先展示 `role=bounce` 的中心联系人，旧 SQLite 仅作为兼容回退。
- 验证：中心收件箱渲染测试通过。

### 联系人详情跳到 CRM 看板后无法定位

- 现象：点击“在CRM中查看”只到看板，没有自动打开或定位当前联系人。
- 原因：跳转只携带 `view=board`，丢失中心联系人和客户编号。
- 修改：深链统一携带 `centerContact` 与 `centerCustomer`。
- 验证：详情页跳转测试通过。

### 发信成功后任务状态可能不推进

- 现象：全量测试出现发送成功的后台异常 `onCampaignSendSent is not a function`；任务可能已发信但触点没有推进。
- 原因：动态导入 campaign 服务的 Promise 只有同步 `try/catch`，内部拒绝无人处理。
- 修改：所有 sent/failed 动态回调统一进入带 `.catch()` 的通知函数并记录错误。
- 验证：发送管线和 campaign 定向 61 项通过；完整测试无未处理异常。

### 测试全量运行时大量“随机超时”

- 现象：完整测试容易出现大量 5 秒超时，但单文件正常。
- 原因：JSDOM、Ant Design 和 Electron 集成测试无界并发争抢 CPU。
- 修改：Vitest 默认限制为 1–4 个 worker，并修正自动回复/退信的过期状态断言。
- 验证：完整 `npm test` 1720 项通过、181 跳过、0 失败。
