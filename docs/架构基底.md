# 架构基底

## 2026-10-23 账号归档与恢复

中心账号生命周期区分“停用并归档”和“恢复账号”。账号归档使用现有 `deleted_at` 软删除，邮箱唯一记录和原 `user_id` 保留用于审计及历史引用；普通用户查询默认排除归档账号，`state=archived` 仅允许超级管理员读取。归档账号必须通过 `user.restore` 显式恢复并设置新初始密码，恢复后启用、强制首次改密、旧会话保持撤销、原产品授权保留。`user.create` 和 `createSalesAccount` 自助注册遇到归档邮箱必须返回冲突并提示联系管理员，不能静默恢复或接管。彻底清除不在日常管理入口中提供。

## 2026-10-22 发送任务自动命名

发送中心创建和编辑草稿时，任务名改为可选。空名由共享纯函数扫描现有任务名，生成首个未占用的 `任务N`；自定义名称不参与编号占用。后端创建/更新服务负责最终生成，renderer 使用同一任务列表规则展示第 4 步占位和确认名称，IPC 返回实际任务名，避免界面与落库不一致。任务删除后空出的默认编号可重新使用。

## 2026-10-22 联系人核心链路审计加固

联系人软删除是当前所有查询和导入路径共同遵守的状态边界。工作簿导入与平面导入都必须区分活动、软删除和不可恢复记录：可恢复时复用原联系人 ID，保留 `source/source_detail`、客户关系和历史，递增联系人版本并写 `crm.contact.updated`；不可恢复时在写入公司、客户或映射前失败。客户级编辑、看板搜索和联系人列表统一只把活动联系人视为当前关系。

联系人镜像增量游标只对当前 `format_version` 和同一权限范围有效。格式升级或权限变化时，适配器向同步服务返回空游标，服务必须走完整授权基线，禁止用旧游标继续增量更新一个永远无法 `ready()` 的投影。短期实时读取仍作为镜像不可用时的用户路径回退。

收件箱匹配错误与“没有邮箱”是不同状态，renderer 必须显示具体失败；中心联系人的删除入口根据 `canDelete` 展示，已分配或权限不足的联系人不能先显示可用操作再依赖服务端兜底。每日本地备份若当天文件已存在则跳过重复生成，零字节异常文件保留改名证据后重建。

退信详情的联系人关联以中心镜像为真源。邮件列表 hydration 返回当前邮件的中心链接，renderer 根据 `role=bounce` 展示被退联系人；旧 `inbox_bounce_matches` 只用于没有中心上下文的兼容模式，不能继续让中心已确认的退信关联隐藏在旧表中。

跨页深链必须携带能够重新定位对象的稳定引用，不能只携带目标视图。联系人详情进入 CRM 看板使用中心联系人 ID 与客户 UUID；收件箱进入联系人详情沿用相同引用。服务层通过动态导入调用反向依赖时，必须返回并处理 Promise 拒绝；同步 `try/catch` 不能捕获 `.then()` 内部异常，发信成功/失败回调统一经 `notifyCampaign` 记录错误。

JSDOM、Ant Design 与真实 Electron 测试会占用较多 CPU；Vitest 默认限制为 1–4 个 worker，使全量结果可重复。测试并发不是业务能力，但无界并发导致的大量超时会掩盖真实回归。

## 2026-10-22 收件箱联系人匹配实时回退

收件箱联系人匹配通过 `InboxCenterContactPort` 读取当前账号可见的联系人。`crm-offline.db` 的完整镜像可用时继续本地读取；镜像格式未就绪、正在同步或损坏时，适配器调用现有中心联系人查询并分页读取全部授权记录，不再把未就绪镜像直接映射成空数组。匹配读取以 `baseUrl + userId + permissionKey` 校验账号范围，中心失败保持失败结果，避免把服务故障显示成“没有匹配联系人”。

分页与完整性检查集中在 `src/main/services/contact-match-reader.service.ts`；transport 和 renderer 不直接访问中心数据库，也不新增匹配专用表。发件人和正文邮箱使用同一短时联系人读取结果，联系人新增等中心写操作会清除该结果并复用原有 `contacts` 查询失效链路。

中心 CRM 写操作会把匹配读取标记为“必须实时”，直至下一次完整镜像基线重写完成，防止删除或恢复成功后仍命中旧本地副本。匹配来源除发件人和正文外，也包含收件人/抄送中已经存在的中心联系人；地址头中的未知内部邮箱不会生成添加入口。联系人新增成功后由客户页返回来源邮件，原收件箱匹配查询随即失效并重新读取。

联系人导入对软删除邮箱采用显式恢复：只有具备原联系人删除权限且客户归属允许时才恢复同一联系人记录，递增联系人版本并写 `crm.contact.updated` outbox；未授权或客户归属不同则返回受限冲突，不创建猜测公司。终态导入回执会结束前端幂等请求，只有未知网络结果才保留原操作键重试。

## 2026-10-21 登录不再自动创建发信账号

中心登录与发信邮箱配置彻底分离。登录只建立中心身份和本机账号资料库，不再把中心登录邮箱、中心密码或阿里云默认服务器改写成 `email_accounts` 记录。发信账号只能由用户在设置页明确新增或编辑，邮箱服务商密码/授权码也必须单独输入；新增账号仍执行 SMTP，并可选 IMAP 真实性验证。

编辑既有账号时，邮箱、显示名、SMTP/IMAP 地址、端口和签名可以保存；更改邮箱会检查本机账号唯一性。密码留空时保留原凭据且跳过在线验证，填写新密码时重新验证并加密。保存失败必须显示主进程错误，不能吞成“已更新”。

## 2026-10-21 收件箱刷新进度与 IMAP 续抓

收件箱刷新继续复用 `inbox:fetch` 与 `inbox:fetchProgress`，但进度载荷升级为按账号的阶段快照：`connecting/searching/scanning/calibrating/processing/post_processing/complete/failed`，并携带当前批次 `scanned/total/newCount/remaining`。共享契约在 `src/shared/inbox.ts`，IMAP/POP3 在 services 层上报协议阶段，收件箱服务补充保存、中心匹配和抓取后处理；renderer 只负责映射显示，不推断后台状态。

IMAP 常规增量取最近 6 天窗口，并额外检查账号是否已有至少 200 封入站邮件；不足时把服务器最新 200 个 UID 并入本轮扫描，已有邮件按 Message-ID 去重，只补缺量。常规水位和最近 200 补拉共用每轮 500 封上限，水位批次优先，补拉候选随后追加；`src/main/core/inbox-fetch.ts` 以 UIDVALIDITY + 最后 UID 推进常规游标。POP3 没有稳定可续游标，继续只检查最新 40 个序号。刷新会等待退信关联和 Sent 探测完成后再结束；正文缓存继续异步限速预取，不阻塞刷新。进度弹窗与抓取任务已解耦，关闭弹窗只转后台，刷新按钮在任务结束前可重新打开进度。

## 2026-10-21 只读系统运行摘要

管理中心增加一级“系统运行”只读页面。核心契约 `OperationsSummary/OperationsCheck` 复用管理看板的 `healthy/attention/offline/not_connected` 状态；service 只对 token 做摘要并调用 repository；PostgreSQL adapter 读取数据库大小、服务器 `statfs` 和部署 `package.json` 版本；transport 追加固定内部地址的 Navigator 健康检查。备份监控明确为未接入，不虚构最近备份时间。

该契约仅暴露显示值，不返回数据库 DSN、主机路径、环境变量、日志、Token 或任意命令。页面复用现有管理中心管理员/审计员读取边界，没有新增迁移、依赖、IPC 或写能力。后续发布/备份按钮必须另建受限运维代理和可审计作业，不允许管理网页直接执行 Shell 或挂载 Docker Socket。

## 2026-10-21 中心账号资料与成长读取

中心身份新增只读资料摘要边界：`GET /api/account/profile` 先验证当前 API 会话，再按会话用户读取 `identity.users.display_name`、`identity.user_profiles` 和 `identity.account_growth_projection`。返回 `AccountProfile { userId, displayName, avatarId, bio, growth }`；资料行或投影不存在时 `avatarId` 使用 `default`、成长返回 `null`，不把缺失解释为 0 经验。等级和本级进度从共享总经验按 Navigator 既有 50 级循环规则派生，中心投影仍是可重建摘要。

桌面经 `online:account-profile` 单一 IPC 进入主进程中心适配器，renderer 不持有令牌。账号页保留原双栏布局，将中心资料映射到既有 `AccountProfileExtras`；头像只保存白名单 ID，同一套预设资源随 Prospector 打包，不把 Navigator 地址、Cookie 或业务数据库耦合进中心。Navigator 航线/群聊偏好和 Prospector 发信身份仍属各产品，不进入本摘要。

`scripts/migrate-navigator-account-profile.mjs` 默认只读盘点，只有 `--apply` 才在中心事务内更新显示名、头像、显式旧账号映射、经验事件和投影。迁移按旧业务 ID 与中心映射或唯一邮箱解析账号，发现中心资料、成长总量、事件时间或源端不存在的事件则拒绝写入。事件 ID 由来源账号与旧事件 ID 生成稳定 UUID，重复执行不重复记经验；事务提交前同时核对事件数量和成长投影，并写管理审计。正式迁移已于 2026-10-21 在备份后执行。

Navigator 已切换为持续同步：共享资料保存先调用中心，再保存产品偏好；业务经验写入本地不可变事件和 `account_growth_sync_outbox`，登录、账号页读取及后续业务动作补传中心。中心按来源产品、规则版本、每日上限和唯一主题键记账。本地显示名和经验表保留历史/业务镜像，但中心资料与成长投影是 UI 真源。

密码修改同样以中心为唯一真源：Prospector 使用桌面会话改密端点，Navigator 使用 `/api/account/password`。两个端点最终更新 `identity.credentials` 并撤销旧会话；中心模式下 Navigator 本地 `operators.password_hash` 不参与改密，也不能被单独更新。

## 2026-10-21 客户创建实时通知补齐

`RuntimeConfig.interruptedBatch` 保存异常退出时被启动阶段认领的批次。它与 `runningBatch` 分离：前者用于发送中心的只读提醒和明确恢复，后者只表示当前运行中的发送引擎。恢复成功后清除 `interruptedBatch`；用户选择暂不恢复时保留它。
