# 架构基底

## 2026-10-09 后端优化（0.9.0-alpha.1）

- `core/signature.ts`、`core/html-text.ts` 为无 IO 的签名提取与 HTML 文本转换；`services/enrichment.service.ts` 只处理匹配来信的空字段回填，24 小时内成功回填仅执行一次，未知或多义公司不创建、不写入。收件箱正文写入后用后台任务回填，不阻塞抓取响应。
- `renderer/lib/cacheDeps.ts` 是数据域与查询前缀的唯一失效映射。`App` 监听既有收信/发信事件，确保页面未挂载时也更新缓存；不增加主进程广播协议。
- `db/search-index.ts` 用命名迁移 `v0.9-search-fts5` 创建 FTS5 虚拟表与同步触发器。只索引 Latin/数字词；原始标题和正文作为 UNINDEXED 字段保留，中文使用 LIKE。旧记录迁移回填预览，`services/search.service.ts` 仅从本地正文缓存后台补全文，不为搜索访问邮箱。已有全文的记录不会在每次启动重新回填。
- `shared/search.ts` 定义搜索 DTO；`transport/search.ipc.ts` 只转发 `search:global`；preload 白名单由 contract 自动展开。全局搜索入口使用应用 Ant Design 主题，摘要以 React 文本与 mark 高亮渲染，不注入返回 HTML。
- `shared/crm.ts` 定义跟进阈值默认值与归一化规则。现有 `send/config.json` 新增 `crm.silentOverdueDays`（默认 5）与 `crm.warnDays`（默认 3），均为 1–365 天的整数且预警不大于逾期。`system:updateConfig` 深合并配置，拒绝非法阈值；CRM 返回 `overdueDays/warnDays`，看板只使用服务端的沉默天数和逾期判定。显式提醒仍以到期时间优先。
- 阶段切换与 `type=stage` 活动在同一事务写入；列表、详情的最近跟进排除 stage/reminder。`extra.stageChangedAt` 保留首次已知管线兜底时间，避免无跟进的老客户因切阶段重置沉默时长。
- Drizzle 的 `idx_interactions_contact_id` 与 `idx_inbox_matched` 声明对齐现有建表 SQL；无新增业务列和重复索引，无新增 npm 依赖。

搜索迁移已生效后回退旧代码，必须先按 `docs/backend-optimization-acceptance.md` 的步骤移除搜索触发器和虚拟表，保留业务表；旧代码未注册 `search_latin` 函数，不能直接带着触发器写库。

## 模型接口类型

`ai/providers.json` 的 `wireApi` 标记服务商使用 `chat_completions` 或 `responses`；旧档案缺字段时按 Chat Completions 读取。激活档案同步 `AGENT_WIRE_API` 到 `.env`，轻任务独立配置可选 `LIGHT_WIRE_API`；两者缺省均为 Chat Completions，轻任务未配置时沿用主端点。`endpoint.service.ts` 统一解析接口类型与 Responses 正文；密钥仍用现有 `AGENT_KEY_ENV` 指针，不新增依赖。Responses Agent 使用已安装的 Agents SDK 并设 `store: false`，不复用 Codex 登录状态。

## 发送恢复状态

`RuntimeConfig.interruptedBatch` 保存异常退出时被启动阶段认领的批次。它与 `runningBatch` 分离：前者用于发送中心的只读提醒和明确恢复，后者只表示当前运行中的发送引擎。恢复成功后清除 `interruptedBatch`；用户选择暂不恢复时保留它。

## 架构边界检查

`npm run check` 运行 `scripts/check.mjs`，用标准 Node 词法读取源码依赖，拒绝新增的 `transport -> DB/schema`、`service -> Electron`、`renderer -> main` 依赖，以及 transport 外注册的 `ipcMain.handle`。`npm run test:architecture` 覆盖检查器自身的解析和规则行为。

既有违反边界的依赖必须逐项登记在 `scripts/architecture-baseline.json`，每项都带整改编号、原因和到期日。检查器只放行精确文件、规则和模块标识完全匹配的例外；新增、过期或已不再命中的例外都会使检查失败。整改完成时先删除对应基线项，再提交代码。

## 发信适配器

src/main/adapters/smtp.adapter.ts 承担账号读取、SMTP 连接池、TLS、HTML 图片 CID 处理与断线重连。send.service.ts 通过 setSendBccFn 接收适配器；transport/send.ipc.ts 只装配适配器、注册通道和转发请求。测试发信和队列发信共用该端口。架构基线已清零，新增 transport 直读数据库由 npm run check 拒绝。

## PR 自动验证

.github/workflows/verify.yml 在 pull request 和 main 推送时，用 Windows 运行器从锁文件安装依赖，并执行架构边界检查、检查器自身测试、TypeScript、Vitest 与桌面 bundle 构建。工作流只有 contents: read 权限，不注入业务密钥，不执行真实发信；GUI 冒烟需独立验证。
