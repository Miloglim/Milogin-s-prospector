# 运价本地库 HTTP 接口 · 字段对接说明

> 生成时间：2026-09-06（基于线上实测返回，非文档推测）
> 服务：`http://<主机>:8788`（局域网），读接口无鉴权，写入需 token。

## 1. 端点

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/rates` | GET | 运价查询，参数 `pol pod route carrier ctype group status q limit offset` |
| `/api/space` | GET | 舱位查询，同上另加 `stype` |
| `/api/rates_grouped` | GET | 折叠视图专用（按 carrier/route/pol/pod/etd 分组，含 history），做数据同步**不要用这个**，用 `/api/rates` |
| `/api/stats` | GET | `{ratesTotal, ratesCurrent, spaceTotal, groups, carriers, latestMessage}` |
| `/api/options` | GET | 筛选枚举 |
| `/api/push` | POST | 写入（表头 `x-push-token`；**请求体键是中文字段名**，见 §5） |
| `/images/<文件名>` | GET | 报价截图 |

## 2. 响应外层（rates/space 同构）

```json
{ "ok": true, "total": 1477, "limit": 50, "offset": 0, "rows": [ ... ] }
```

- 失败：HTTP 500/400 + `{"ok": false, "error": "..."}`；未授权写入：401
- `limit` 上限 500；分页用 `offset`
- 参数值含中文必须 URL 编码（如 `status=%E5%BD%93%E5%89%8D%E7%94%9F%E6%95%88`）

## 3. 行字段别名表（实际返回的键名，snake_case 英文）

**/api/rates 行**（与"豆包文档"别名逐一核对过）：

| 别名表写法 | 实际键名 | 类型 | 说明 |
|---|---|---|---|
| pod | `pod` | str\|null | 目的港，** rates 表基本不为 null；space 表可能为 null** |
| pol | `pol` | str | 起运港 |
| route | `route` | str\|null | 航线（南美东/南美西/加勒比/墨西哥/中美洲/美东/美西） |
| carrier | `carrier` | str\|null | 船司 |
| container_type | `container_type` | str\|null | 柜型，**约 1/4 记录为 null**；枚举仅 20GP / 40HQ/HC / 40NOR |
| freight_usd | `freight_usd` | **str**\|null | 海运费，**字符串如 "6815.00"，不是数字**，取数需 parseFloat |
| validity_raw | `validity_raw` | str\|null | 有效期原文（如 "9.5托9.8"） |
| valid_from / valid_to | 同名 | str\|null | 结构化有效期，YYYY-MM-DD 或 null |
| etd | `etd` | str\|null | 船期 ETD |
| free_days / dead_freight | 同名 | str\|null | 目免 / 亏舱费 |
| remark | `remark` | str\|null | 备注 |
| source_group | `source_group` | str | 来源群名 |
| sender | `sender` | str | 发送人 |
| message_time | `message_time` | **str（格式不统一）** | 多数为 `"2026-09-03"`，新数据带时间 `"2026-09-06 17:59"`；**字符串比较排序可用，但别假设固定格式** |
| message_text | `message_text` | str | 消息原文（逐字） |
| image_url | `image_url` | str\|null | **截图文件名**（如 `"1477-宁波-nb_zim_mx.png"`），不是 URL；取图拼 `/images/` + encodeURIComponent(文件名) |
| status | `status` | str | rates 枚举：`当前生效` / `已被覆盖`；space 枚举：`当前有效` / `已被覆盖`（**两表字面量不同**） |
| overridden_time | `overridden_time` | str\|null | 仅 rates 有 |
| synced_at | `synced_at` | str | 本机入库时间 "YYYY-MM-DD HH:MM:SS"，**做增量同步按这个字段** |
| id / content_key | 同名 | int / str | 自增主键 / 内容指纹（同一条记录跨端稳定，可作幂等键） |
| mid | `mid` | str\|null | 钉钉 openMessageId（新数据才有） |

**/api/space 行**额外/差异字段：`vessel_voyage`（船名航次）、`cutoff_raw`（截关原文）、`box_desc`（箱型箱量描述）、`box_qty`（箱量）、`space_type`（现舱/加班船/约舱/售罄/舱位紧张/截关截单/撤载改期/箱子动态）、`price_usd`（**str**|null）；没有 `freight_usd / validity_raw / valid_from / valid_to / overridden_time`。

**通用空值约定：缺字段值是 `null`，不是空字符串**。

## 5. 写入方向键名不同（注意别混）

`GET` 返回英文键；`POST /api/push` 的 `records` 里用**中文字段名**（与钉钉 AI 表格列逐字一致）：
`起运港 目的港 航线 船司 柜型 海运费USD 有效期船期 目免 亏舱费 备注 来源群 发送人 消息时间 消息原文 运价图片 有效期起 有效期止 船期ETD 被覆盖消息时间 记录状态`（舱位表对应：船名航次/船期截关/船期ETD/箱型箱量/柜型/箱量/舱位类型/价格USD…）。
体：`{"table":"rates"|"space","records":[{...}]}`，按内容指纹幂等，重复推不增行。

## 6. 排查提示

- "目的港全为空" 最常见原因：①别名表用了 camelCase（pod 写成 podOk 之类不会，写成 `destination_port`/`podName` 会取不到）；②把 rates 和 space 的键混用（space 的 pod 本来就可为 null）；③只解析了 `rows` 外层没进 `rows[]`。
- 不确定时先 `GET /api/rates?limit=1` 打印整个 JSON 对键名，别猜。
- 增量同步建议：记下本次最大 `synced_at`，下轮拉全量分页后按 `synced_at > 上次水位` 过滤（当前未提供 since 参数，需要可让服务端加）。
