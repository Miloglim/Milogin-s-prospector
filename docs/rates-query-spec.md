# 查运价规范（清洗 → 归属 → 呈现 → 报价表）

日期：2026-09-07　状态：规范已定，代码待落　适用：Prospector 查询侧
上游文档：匹配与定论的三段式见 `docs/rates-query-fallback-spec.md`；同步链路见 `docs/rates-remote-source-spec.md`
台账侧目标结构（下一期在入库层实现，本轮不动台账数据）：见本文 §7

## 0. 边界（本轮做什么、不做什么）

- **只规范查询侧**：不改台账（board `freight_rates`）表结构、不重灌存量、不动心跳写入口径。
- **真源现状（2026-09-07 实测）**：台账已从内网 `192.168.189.229:8788` 换成公网 HTTPS
  `https://l5ruag9m.qwenwork.host`（`RATES_REMOTE_URL` 可覆盖）；`/api/stats` = 运价 3748 条、舱位 381 条、
  最新消息时间就是当天。本地镜像只有 428 行——**落后一个数量级**，调试与验收前先在运价页点一次同步。
  可达性探测与同步必须走同一网络通道（都用 `netFetch`），否则会出现"探测说连不上、同步却成功"的口径分裂。
- 台账现在仍是脏长表（一条消息按 pod 拆行、一柜型一价、港名粘连、多港合并、`1000/2000` 这类多价与目免只在原文里）。
  本轮由**读侧清洗器**在查询时把它洗成规范形态。
- 清洗器是**纯函数 + 页面与助手共用一份**。只洗在 agent 工具里会造成"助手干净、运价页脏"的第二套真相。
- 原文必须进镜像：三列价的解析素材大部分只在 `message_text` 里，不存原文就只能靠猜。
  原文只在清洗器内部使用，**不进 IPC 展示投影**（镜像行过 IPC 会被整表轮询，几 KB×全量会拖慢界面）。

## 1. 规则链（用户提到运价 → 一定走到表）

1. **凡提到运价必查台账镜像**（`quote_search`），不得凭记忆、常识或外部印象答；
2. **先机械洗，再语义归属，最后定论**——三段式沿用 `rates-query-fallback-spec`：
   跨字段并集匹配 → 空结果回候选让模型换词重试一次 → 两轮不过才分清"镜像没跟上真源"与"确实没有"；
3. **呈现结果后问一句**要不要做成客户报价表；**同意才出报价表**（不静默生成文件）；
4. 报价表落盘走 `export_artifact`（写盘=生成，每次弹确认卡，符合审批红线）。

## 2. 读侧清洗器（新模块 `src/main/services/rates-clean.ts`，纯函数无 IO）

输入：镜像行（含 `podRaw/pol/carrier/container/containerRaw/oceanUsd/freeDays/note/etd/status/validFrom/validTo/messageText`）。
输出：`CleanQuote`——`carrier / pols[] / pod / p20 / p40 / pNoR / freeDays / etd / validFrom / validTo / note / source / sender / msgTime / syncedAt / state`。

### 2.1 起运港归一（固定值表）

- 合法值只有十个：**蛇口、南沙、盐田、华南基本港、上海、厦门、宁波、青岛、天津、大连**。
- 识别到的港区/别名要落到固定值：`深圳→蛇口/盐田/南沙`（三者都是深圳港，不能合成一个）、
  `广州→南沙`、`宁波港/NGBO→宁波`、`TAIPEI/高雄/基隆→不映射（非我口岸）`、`Singapore→新加坡（不在十值内，原样保留并标 unverified）`。
- **多港合并必须拆开**，实测分隔符有 `/`、`+`、`；`（全角）、`;`、`、`、`,`、空白与全角括号：
  `全口岸（大连/香港/高雄/基隆/宁波/青岛/上海/蛇口/深圳/新加坡/厦门/天津新港/盐田）`、`青岛+太仓+南沙`、
  `蛇口/香港/盐田/厦门`、`盐田/蛇口`、`天津新港（Xingang）`、`SGH/NPO/YAT/YOK/BUS；TST/HSK`、
  `Dalian, Dalian, Liaoning, China;…;Shekou, Shenzhen, Guangdong, China;…`（英文形态取每段首词再归一）。
  一个词根拆成多港时，同一条运价**按港分行呈现**（读侧拆，不写回库）；客户报价表的 POL 必须唯一，多港一律拆行。
- 归一不了的值不猜，保留原文并打 `unverified`。实测存在但**不在十值白名单**的口岸：
  福州、钦州、汕头、太仓、香港、高雄、基隆、新加坡、横滨（YOK）、釜山（BUS）；
  三字码 SGH / NPO / TST / HSK 含义未确认（YAT 按盐田处理，大铲湾按深圳港区三候选处理）。
  这些确认前一律保留原文 + 标待核实，确认后只需往别名表加行，不改算法。

### 2.2 目的港归一（唯一标准英文港名）

- 剥掉中文译名与国别括注：`ISTANBUL 伊斯坦布尔(土耳其)` → `ISTANBUL`；`SANTOS 桑托斯(巴西)` → `SANTOS`。
- 剥掉尾部航线小字（`… 地东`）——已由同步层 `stripLaneTag` 处理，清洗器再兜一次（页面/历史数据可能仍有）。
- 多港合并串拆开（`;`、`/`、`,`、`、`、`&`、空格分隔的多个全大写词），取用户所问的那个或逐港成行；
  `BALBOA, PA` 这类"港名 + 国家码"只取港名。
- 大小写与别名统一走上游词表 `src/main/services/rates-portmap.json`（随包内联、运行时不读盘；`resolveQueryPod`），
  词表仍是**词表不是数据源**。实测 67 个港、7 条航线（南美东/南美西/加勒比/墨西哥/中美洲/美东/美西），
  **不含真源实际在用的 北非/地东/黑海/拉美/欧基港**——所以航线归属一律以镜像实时反推为准（§2.6），词表只用于港名别名。

### 2.3 船司归一（国际标准缩写/名）

实测真源 26 个值：`合德、外运、未注明、中远海特、SINOTRANS 外运、AKKON、CMA、COSCO、CUL、EMC、EMI、ESL、
FESCO、GSL、HMM、HPL、MSC、MSK、ONE、OOCL、PIL、RCL、TSL、WHL、YML、ZIM`。规则：

- 已是国际缩写（3–4 位大写字母）→ **原样采信**，不改动；
- 中文/长名映射：`中远海特/中远/中远海运→COSCO`、`外运 / SINOTRANS 外运→SINOTRANS`、`达飞/CMA CGM→CMA`、
  `马士基→MSK`、`地中海航运→MSC`、`长荣/EVERGREEN→EMC`、`海洋网联→ONE`、`现代→HMM`、`以星→ZIM`、
  `阳明→YML`、`太平太平洋→PIL`、`赫伯罗特/HAPAG→HPL`；
- `未注明`（及 `未知/N/A/-`）**不是船司名** → 归空：工作结果表显示 `—`，客户报价表 `CARRIER` 给 `/`；
- `合德` 对应缩写未确认 → 保留原文并标 `unverified`（确认后往别名表加一行即可）。

### 2.4 三列柜型价（宽表在读侧合成）

实测口径：`container_type` 只有 `20GP` / `40HQ/HC` / `40NOR` 三值（约 4.5% 为 null）；
`freight_usd` **全库单值、0 行含斜杠**——多价只活在 `message_text` 里，而且**按港分行**。

解析顺序（一步都不许跳）：

1. **结构化列最可信**：`container_type` → 列（`40HQ/HC`、`40HC`、`40GP` 都归 40HQ|HC 列），`freight_usd` → 值；
2. **原文按港定位后再取价**：先在原文里找出**含该行目的港**的行（同港组行也算，如 `ISTANBUL/ IZMIT/ MERSIN/ ALIAGA`），
   只在这些行里解析 `X/Y`（2 价 = 20GP/40HQ|HC）、`X/Y/Z`（3 价 = +40NOR）、`高 X`（40HQ|HC）、`小 X`（20GP）；
   > 真源样例：同一条消息里 `ALEX 4200/5100` 与 `ISTANBUL/MERSIN/ALIAGA 4100/4800` 并存，
   > 而台账已把它拆成 `pod=ALIAGA` 一行。**不按港定位就会把亚历山大的 4200 填给 ALIAGA——报错价比查不到更糟。**
3. **港组共享价兜底**：定位不到本港时，只有当全篇**唯一一处**多价才可整条采用
   （真源样例：`USD3300/3900+` 对 ISTANBUL/IZMIT/MERSIN/ALIAGA 四港同价）；
   全篇有多处不同价又定位不到本港 → **不猜**，三列留空并标 `unverified`；
4. 数字清洗：`$`、`USD`、千分位一律先剥；`USD3300/3900+` 的 `+` 表示另加附加费，价照取、附加费进备注；
5. 同一条运价（同 船司+港组+目的港+有效期）的多行**合并成一行情三列**；三列来源冲突时保留较早一条并标 `unverified`；
6. 合理性：非 100–30000 区间的值不采信（标 `unverified`）；三列全空标"价：三列未解析"。**不填 0、不推算。**
7. **柜型为 null 的行**（实测约 4.5%，且带独立价：同一消息里 `20GP=8444`、`40HQ/HC=10794`、`柜型 null=9894`）：
   这个价**不许塞进任何一列**（塞错列就是错价），改为进备注保留信息（`未标柜型价 $9894`）。

### 2.5 目免 / ETD / 有效期 / 状态 / TT

- **Freetime（目免）**：实测 `free_days` **全库为 null**，值只在原文/备注里且**按国别分**
  （"埃及目免21，土耳其14"、"21 combined"）。所以：结构化列有值就用；否则按本行目的港的国别关键词
  （`ISTANBUL/IZMIT/MERSIN/ALIAGA→土耳其`、`ALEX→埃及`…）在同一片段里取数；再否则只有全篇唯一值才兜底采用；
  多个不同值又定位不到 → 留空，原文已在备注里。采信范围 1–30 天，越界转备注不丢弃。
- **ETD**：实测约 20% 的行有 `etd`。归一为 `YYYY-MM-DD`，兜底顺序：结构化 `etd` →
  **本港定位行**里的"截关+开船"合写（`9.6晚开9.10` → ETD=9.10，前面那个是截关不是 ETD）→ 定位行里的 `月.日`
  （`9.21 蛇口-IZMIT …` 只对 IZMIT 生效）。缺年份按消息时间推，落在过去则 +1 年；解析不出留空、原文进备注，不猜。
- **有效期**：实测约 45% 的行有 `valid_to`；`validity_raw` 形如 `9.1~9.30`，也可能是船期文本（`直航快船CLS 9.11`）——
  两者不能混用。只有一边时不臆造另一边；起止都缺时把 `validity_raw` 原文进备注、报价表 `VALIDITY` 给 `/`。
  是否生效 = `valid_to >= 今天(北京)` 或无止日 → `当前有效`，否则 `已过期`。**不新增存储列**，运行时算。
- **备注**：结构化字段（船司/两港/三价/目免/ETD/有效期）之外的内容一律进备注，与原有 `note` 合并去重；
  原文不进备注（太长），仅在 `unverified` 里指回原文。
- **TT（航程天数）**：两侧都没有这个字段 → **报价表一律 `/`**，禁止用 ETD 差值或常识推算。

### 2.6 航线归属（`Santos → 南美东`、`地东 → 地中海一带`）

- **实时从镜像反推**，不养第二份死词表：某目的港在库里出现过 → 取它的 `lane`；该航线下所有行（含目的港只写航线名的航线级报价）都算相关候选。
- 港区归属（`深圳→蛇口/盐田/南沙`）是常识映射，词表补进 `rates-portmap.json`（属于词表，不是数据源）。
- 归属结论**由模型下**：清洗器只把"这个词在库里属于哪些航线、这些航线下有哪些行"如实标出；
  工具不在内部再调一次大模型（调用方 agent 本身就是模型，重复花一次）。
  模型必须按 `rates-query-fallback-spec` 的候选清单换词重试，不得凭空断言归属。

## 3. 呈现规范（第一张表，给用户看的工作结果）

字段固定顺序：**船司 · 起运港 · 目的港 · 20GP · 40HQ/HC · 40NOR · 目免 · 有效期 · 备注 · 来源 · 发送人 · 入库时间**

- 表格卡由工具机械生成（`userTable` 之外的展示表仍由前端渲染镜像行，二者都走同一清洗器）。
- 未指定起运港时**不追问**：按起运港分组，各给最低价与条数（库里天津 155 / 青岛 148 / 蛇口 102，混排挑最低会报错港）。
- 一行内多个起运港 → 拆行显示，禁止粘连。
- 表下方固定一行时效：**`镜像 N 条 · 最近同步 X · 台账 host 可达/连不上`**（数字全部来自工具返回）。
- 有 `unverified` 的行在表里挂"待核实"标记，回答里必须说明，不得静默抹平。
- 正文不重复贴整张表（沿用既有约定：界面已有表格卡，正文给结论）。

## 4. 客户报价表（要用户同意才出）

**两表分离（2026-09-08 用户定案）**：`quote_search` 返回两张表，各走各的出口，不许拿错——
`userTable` 给用户自己看（标准化透视优先，中文表头，**含报价单截图＝信息来源**）；
`customerTable` 是对外交付物，与回信共用**唯一出口** `customerQuoteTable`（rates-clean 英文十一列），
`total=0` 时两表一律为空（同源铁律不变）。notice 明说两表分工，弱模型只会照指令贴表。

问法固定一句：**「要不要把这份价做成可发客户的报价表？」** 同意后才输出，列与格式写死：

```
CARRIER / POL / POD / 20GP / 40HQ|HC / 40NOR / FT / ETD / VALIDITY / TT / REMARK
```

- `CARRIER`：国际标准缩写；`POL`/`POD`：**唯一港口名，全大写**（`NINGBO`、`SANTOS`），不带国家、不带中文、不多港粘连；
- 三列价：整数，缺失填 `/`；
- `FT`=目免天数，缺失 `/`；
- `ETD` 格式 `16 Sep`；`VALIDITY` 格式 `1-15 Sep`（跨月 `31 Aug – 6 Sep`，跨年补年份）；缺失 `/`；
- `TT` 缺字段 → `/`；`REMARK` 只放客户看得懂的说明（附加费、免费期、直转航），内部溯源（来源群/发送人/入库时间）**不进客户表**；
- **REMARK 全英文铁律**（实测翻车：中文内部备注直发客户）——台账备注过 `rates-clean.customerRemarkEn` 三道闸：
  ① 内部操作语整条判丢（成本价/底价/批价/刷箱/锁价/可以申请/特价合约/对比FAK… → `/`）；
  ② 有限词表机械译英（重柜费→Heavy-duty surcharge、N吨及以上→Nt and above、含→incl.、delay至→delayed to、
  拖班到→shifted to、可以继续收货→open for booking、降价更新→rate update、南美东→S.America、十值口岸→英文名…）；
  ③ 译完仍含中文 → 整条置 `/`。**宁可空，绝不中英混排给客户**；单测用 2026-09-08 会话导出的 9 条真备注钉死。
- 报价表落盘 → `export_artifact`（弹确认卡）；不落盘就在对话里贴 Markdown 表，二者不同时给两张。

## 5. 审批与安全

- 本链路里 agent 只做**读**与**回答**；写盘（导出）与外发（入队/发送）一律人工确认，红线不变。
- 查价时若镜像可疑（>24h 未同步或本轮有未命中）自动静默刷一次再查：**同步是本地缓存重建**，
  只重写 `rate_quotes`/`space_records`，不碰业务表、不外发，失败保留旧数据；节流四条见 `rates-query-fallback-spec` §6。

## 6. 实现顺序与验收

1. 同步补列：镜像加 `etd`/`status`/`message_text`（schema + `BASE_SCHEMA_SQL` + `runMigrations` 补列 + 手工沙箱 DDL 三处）；
2. `rates-clean.ts` 清洗器（纯函数）+ 单测：起运港十值归一与拆多港、目的港标准名剥离、船司缩写、
   `1000/2000`、`1000/2000/1200`、`高2000`、`小1000` 解析、目免 0-30、ETD 解析、状态计算、`TT` 恒缺；
3. 航线归属实时反推（镜像 `distinct lane`）+ portmap 补港区词；
4. `quote_search` 接清洗器：宽表透视、按起运港分组、时效行、`unverified` 标记、报价表征同意的 notice；
5. 运价页 `RateBoard` 用同一清洗器（列表显示干净值、筛选能命中标准名）；
6. 全量：`npm run typecheck` + `npm test` + `npm run build` 三绿；手测「深圳到Santos」「地东的价格」「宁波到曼萨尼略 40HQ」。

## 7. 台账侧目标结构（下一期，不在本轮实施）

入库层直接把宽表与标准名做实，Prospector 读侧清洗即可退役为兜底：

- `freight_rates` 列改为：船司、起运港、目的港、20GP、40HQ/HC、40NOR、Freetime、船期ETD、有效期起、有效期止、
  航线、备注、来源群、消息时间、发送人、原文、图片、记录状态（+ 现有 `content_key`/`synced_at`/`mid`）；
- 一条消息识别出的**每个起运港 × 每个目的港**拆成独立行（多港不粘连）；
- 起运港写十值固定名，目的港写标准英文唯一港名，船司写国际缩写；
- `1000/2000/1200`、`高2000`、`小1000` 这类表述在入库时解析进三列，解析不出的原文进备注；
- 图片沿用 `image_file` 复用机制（一图多行引用同一文件），避免重复落图；
- 记录状态可由 `有效期止` 函数判断 + `已被覆盖` 标记；
- **相同信息源的补充要可追踪**：新增"更正指向"关联（如 `supersedes`/`root_key`），
  让"船停开了"这类后续消息挂回原条目而不是新插一条（本轮不做，规范先记）。
- 新增「动态与行情」表（内容/来源/归属/日期）与每日 AI 总结定时器：独立一期，不进本链路。
