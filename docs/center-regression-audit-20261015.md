# 中心服务失败项核查（2026-10-15）

本轮仅核查，不修复产品代码、前端、数据库结构或公共接口。参考开发规范、知识库项目入口/当前状态，采用 systematic-debugging 定位和独立副本验证。

## 结论

当前 `scripts/online-server.mjs test` 的 135 项测试复跑结果为 **117 通过、18 失败**，不是固定的 17 项失败。其中 13 项与当前已批准的业务规则不一致或受前置失败连带影响；4 项来自密码测试样本不符合现行字符规则；1 项是保留的旧激活补发接口缺陷。另发现不在这 18 项中的真实注册校验缺口。

这些结果不能解释为当前登录、联系人分配与同步全部失效，也不能解释为当前中心回归已经全绿。

## 两个真实接口问题

### 1. 注册和改密规则不同

位置：`server/services/desktop-session.ts` 的 register 仅检查邮箱宽松格式和密码长度，没有使用 `PASSWORD_PATTERN`；changePassword 及管理端密码消费已检查该规则。账号邮箱同样没有落实禁止中文的既定约束。

独立副本中通过真实 HTTP `/api/auth/desktop/register` 与 PostgreSQL 验证：含符号、空格、中文的三种密码均返回200；中文邮箱返回200；合法字母数字密码返回200；不足6位返回400。测试只替换密码计算适配器为合成值，路由、服务、存储和约束为真实代码；没有测试真实用户凭据。

这是既定业务规则不一致，并非本轮证明发生了账号越权。后续应统一注册/创建账号/改密的校验来源，并保留已有密码登录兼容，不随意禁止标准邮箱必需的 `@`、`.` 或合法邮箱符号。

### 2. 旧激活补发失效

位置：`server/adapters/postgres/admin-repository.ts` challenge.issue 分支，只要邮箱存在即拒绝 activate，即使该账号未激活且未设置密码。这使过期激活链接无法补发。

该兼容入口不在当前创建账号页面调用中；HTTP challenge.issue 仅 test_mode 开放。正常创建账号使用 user.create 和首次改密，不能把本缺陷描述成当前所有账号无法创建或登录。下一修复节点应选择保留并补齐契约，或明确退役兼容入口，不能只删测试掩盖接口残留。

## 补充验证与接口残留

另运行12文件59项定向检查：57通过、2失败。已通过的范围包括联系人分配/接受及同公司其他联系人隔离、中心列表权限与分页、邮件事件幂等与实际发送轮次、身份权限、删除保护、跟进任务，以及合法新密码下的桌面会话与强制改密。注册诊断用例的“通过”表示成功复现上述校验缺口，不表示注册规则验收通过。

两项失败：旧激活补发；商机通知测试写死全库仅3名授权接收者，当前库还有其他具备 read.all 权限的管理员，因此两事件产生18条而非6条通知。源码允许这些管理员接收；仅在副本外层回滚事务中停用无关测试账号后，商机原10项测试全部通过。该实验支持测试未隔离全库管理员造成数量漂移，不证明所有通知安全场景均已覆盖。

残留HTTP路由 `/api/crm/leads/:id/assign` 和 `/claim` 仍注册，但写操作已明确拒绝；正常联系人分配使用现有 assignment-create/accept/reject/cancel。当前桌面注册表没有重新接通旧 assign/claim 通道。本轮不新增、不删除IPC/HTTP，不恢复第二套归属写链路。后续测试入口应纳入当前联系人、邮件、身份生命周期、任务与商机的真实PG检查，并统一隔离/清理数据，不能长期只跑旧135项。
