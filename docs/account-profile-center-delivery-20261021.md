# 中心账号资料与成长读取交付

日期：2026-10-21
版本：`0.54.0-alpha.1`，工作区未发布

## 已实现

- 中心 `GET /api/account/profile` 按有效 API 会话返回共享显示名、头像 ID、简介和成长摘要。
- Prospector 新增 `online:account-profile` IPC、主进程服务和中心适配器；账号资料页保留现有布局，读取中心昵称、预设头像、等级与经验进度。
- 成长等级和本级进度由中心总经验按既有 50 级循环规则派生，缺失数据仍显示未知。
- Navigator 预设头像以白名单 ID 共享，Prospector 打包同套 61 个 PNG，不复制 Navigator 业务 API 或会话。
- `scripts/migrate-navigator-account-profile.mjs` 默认 dry-run，显式 `--apply` 才写中心；包含账号解析、冲突预检、稳定事件 UUID、管理审计、幂等写入，以及事务内经验事件和成长投影双重核对。

## 验证

- 定向 14 项：成长派生、服务会话绑定、IPC 注册、账号页头像/等级渲染通过。
- 隔离 PostgreSQL 真实 HTTP 13 项及 schema 1 项通过，覆盖匿名 401、登录会话读取专用资料、缺失资料保持未知、成长派生和响应不泄露凭据。
- 正式来源 dry-run：源端 13 个 active 账号，可解析 6 个中心账号、5098 条经验事件；7 个账号因无中心业务映射跳过；冲突 0。管理员对应 5088 条事件、循环 7、等级 28、本级 16/21 XP。
- 隔离 PostgreSQL 临时库完整执行两次 `--apply`：第一次写入 2 条事件、资料、映射和投影，第二次不重复事件；随后篡改一条中心事件，第三次执行被预检拒绝。显示名、头像、总经验 30、等级 3、今日 18 XP 和管理审计均核对通过，临时库已回收。测试入口为 `npm run test:account-profile-migration`。
- `node --check` 迁移脚本、typecheck 通过。隔离 schema 测试单独运行通过；多个 PG 测试文件并行启动迁移时曾有一个文件因共享测试库迁移竞争失败，串行重跑通过，不能表述为并行稳定性通过。

## 当前边界

正式中心尚未执行 `--apply`，因此生产账号资料、头像和成长当前仍为空，页面尚未出现 `Zayne` 和等级 28。迁移会更新生产显示名、资料、5098 条经验事件、成长投影并为管理员补一条显式旧账号映射，属于生产写入，需单独授权。迁移后还需重新编译/重启正式中心并重启桌面客户端加载新 IPC；本节点没有新增依赖或数据库迁移版本。

本节点只有一次性迁移和中心读取，没有 Navigator 的共享资料写入或持续经验上报。Navigator 的 `/api/account/profile` 与成长接口仍读写本地 `operators` / `account_experience_events`，因此正式迁移后若继续在 Navigator 改名、换头像或获得经验，两产品仍会再次分叉。正式迁移前必须先确定 Navigator 的共享资料写入与经验事件上报/冻结策略；不能把 dry-run 零冲突等同于长期同步完成。

## 回退

代码回退到 `0.53.2-alpha.1` 即可停止读取新接口。正式迁移执行前应先备份中心/Navigator PostgreSQL；中心写入在单事务内完成，失败整体回滚。执行后若需回退资料，应按迁移前备份恢复，不能仅改客户端隐藏字段。
