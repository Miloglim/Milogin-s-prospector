# Prospector CRM 核心权限与状态契约

日期：2026-10-29
状态：已批准，CP0 冻结

本文件把主计划中的产品决定落成可测试规则。实现与本文件冲突时，以本文件为准；任何改变都先更新本文件、主计划和对应测试。

## 1. 角色与关系

| 概念 | 持久化事实 | 不做什么 |
| --- | --- | --- |
| 超级管理员 | 中心 `admin` 或身份管理员 | 不自动成为联系人负责人，不写入团队普通成员 |
| 运营管理员 | 中心 `operations` | 不按运营组相互隔离运营线索 |
| 销售用户 | 中心 `sales` | 不通过团队、搜索、导出、共同编辑查看其他销售客户 |
| 团队负责人 | `crm_teams.leader_user_id` 的关系身份 | 不新增全局 CRM 主管角色，不改变销售角色本身 |
| 审计员 | 中心 `auditor` | 默认不读取客户正文，不参与业务写操作 |

一个普通销售只属于一个叶子团队。一个负责人可以负责多个团队。负责人负责的每个团队都会在负责人工作台出现，但负责人只对直属成员承担监督关系。成员显示分组只改变团队页展示，不改变线索归属或权限。

超级管理员共享公司级组织根。运营管理员是治理角色，不伪装成团队节点。运营组是来源、组织和批量分配标签，不是鉴权分区。

## 2. 数据范围

### 2.1 联系人范围

| 场景 | sales | operations | admin | auditor |
| --- | --- | --- | --- | --- |
| 本人 `origin=personal` 联系人 | 读写（受字段规则） | 不可见 | 可监管读取 | 不可见 |
| 本人当前负责的 `origin=operations` 联系人 | 读写（受字段规则） | 共享运营池，可读写 | 可监管读取 | 不可见 |
| 其他销售的本人或分配联系人 | 不可见 | 共享运营池仅限 `origin=operations` | 可监管读取 | 不可见 |
| 已接受的字段共享 | 按 grant 读写 | 不因共享获得额外权限 | 可监管读取 | 不可见 |
| 直接下属当前负责的联系人 | 不通过普通列表可见；仅监督摘要/详情 | 正常运营池范围可见 | 可监管读取 | 不可见 |

主管不因“负责人”身份获得成员 `origin=personal` 联系人的普通编辑、删除、导出或发信权。主管可按监督契约查看成员业务摘要、邮件摘要和按需邮件详情；每次详情读取写审计。不得用普通联系人列表、分组计数、离线镜像或 Agent 搜索绕过该边界。

### 2.2 客户数据可见级别

| 数据 | 本人/负责人 | 直属主管监督 | operations | admin | auditor |
| --- | --- | --- | --- | --- | --- |
| 联系人列表/搜索 | 是 | 否（仅按成员进入） | 运营池 | 全局监管 | 否 |
| 联系人详情 | 是 | 按需，审计 | 运营池 | 全局监管 | 否 |
| 联系历史/跟进 | 是 | 摘要及按需详情，审计 | 运营池 | 全局监管 | 汇总审计事件 |
| 邮件标题/分类/摘要 | 是 | 是 | 运营池 | 全局监管 | 否 |
| 邮件正文/附件 | 是，本地全文 | 按需，中心摘要/元数据及审计 | 同左 | 按需，审计 | 否 |
| 导出联系人 | 是，当前普通范围 | 否 | 运营池授权范围 | 监管范围，显式审计 | 否 |
| 线索分配 | 接收/接受 | 监督和接收分配（负责人本人） | 发起/撤回 | 全局监管 | 否 |
| 团队树 | 本人团队 | 所管理团队子树 | 全部运营相关团队 | 公司级全树 | 组织审计摘要 |

“可监管读取”不等于普通 `leads.develop`。实现必须使用独立能力/服务路径，例如 `contacts.monitor`，返回专用 DTO，且禁止写操作、发信、导出和批量搜索。

### 2.3 邮件与 AI

- 中心只保存邮件标识、元数据、摘要、分类、结构化业务信号和关联；全文与附件保留在客户端本地。
- AI 只能新增或更新分析投影，不能修改负责人、当前归属、客户阶段、成交结果或人工已确认字段。
- 人工修改优先于 AI；人工锁定后，迟到的 AI 结果只能保留在分析历史，不得覆盖当前结论。
- 自动回复、退信不是客户本人回复。内部邮件、供应商、通知、垃圾邮件和无关邮件不改联系状态、不生成客户待办、不进入销售指标。
- 同一 `mailboxKey + messageKey + contactId` 的分析必须幂等，并携带 `analyzerVersion`、输入先后序号和人工优先标记。

## 3. 联系状态

联系状态固定为：

`uncontacted -> contacted | bounced | autoreply`

`contacted -> replied | bounced | autoreply`

`replied -> contacted` 只允许人工显式更正；自动重放、按记录时间晚到或普通 AI 运行都不能回退。

`bounced -> autoreply -> replied` 可以由更新时点的人工事实或更高优先级的有效邮件事实覆盖。人工事实在同一发生时间获胜。

关系阶段独立：`cold`、`reaching`、`quoting`、`trial`、`cooperating`、`lost`、`other`。阶段变化不制造“已触达”；只有 `contacted/replied/bounced/autoreply` 进入跟进看板。

## 4. 线索入口与冲突

所有手工新增、平面导入、工作簿导入、Agent 导入、API 写入、软删除恢复和迁移恢复都必须调用同一个冲突网关。

判定优先级：

1. 规范化邮箱完全一致：终态冲突。
2. 规范化公司域名完全一致：强关联候选，默认阻止静默新建公司。
3. 规范化公司名完全一致：强候选。
4. 去掉法律后缀、公司停止词后的高相似公司名：人工确认候选。
5. 其他：允许新建。

销售只能拿到自己授权范围内可解释的候选信息，不能通过冲突接口枚举他人客户。无写权限的记录只能返回“受限冲突”，不返回公司详情。软删除记录命中邮箱时，只有原删除权限、当前归属和组织规则都满足才恢复同一条记录，并保留历史；否则返回受限冲突。

## 5. 分配状态机

```
pending -> accepted | rejected | cancelled | expired
accepted -> pending_transfer -> accepted(new owner) | transfer_cancelled
```

- 同一联系人最多一个 `pending`、`accepted` 或 `pending_transfer`。
- 分配前联系人继续归原负责人；接受后才改变当前负责人。
- 分给销售成员时，服务端自动计算直属主管，不接受前端任意通知人列表。
- 分给负责人本人时，不自动向该负责人的成员共享。
- 所有分配记录带 `source_unit_id`、`supervisor_user_ids`、创建/到期时间和归属历史。
- 超时扫描只处理 `pending`，必须幂等；接受与超时并发时只有一个终态成功。
- 转交必须由当前负责人或运营管理员发起，使用新状态和版本；旧负责人立即失去普通写权限，但监督和审计历史保留。
- 通知已读、接受请求和接收获批是三个不同事实。

## 6. 任务与主管关注

邮件分析先生成“行动建议”，满足固定强规则（明确询价、要求报价、投诉、承诺未履行）或人工确认后才进入正式待办。任务按客户、线程和行动类型去重。

主管关注项独立于客户任务，状态为：

`open -> acknowledged -> resolved | dismissed`

它只表达“主管希望成员关注”，不能替代成员完成跟进，也不能直接修改客户字段。成员完成后保留处理结果和审计。

## 7. 团队状态

```
invited -> accepted -> active
invited -> declined | cancelled | expired
active -> left | removed
```

- 邀请、接受和成员变更使用版本与幂等键。
- 团队负责人可管理团队结构；运营管理员可治理团队；超管可监管全树。
- 负责人变更不修改全局角色，不自动转移联系人。
- 团队被删除/解散前必须先处理负责人、成员和下游团队；不能级联删除客户事实。

## 8. 指标与客户分级

指标实时从事实查询或短期 TTL 缓存派生，不保存“成员能力结论”字段。至少包含领取耗时、领取后首次处理耗时、有效回复耗时、领取到成交耗时、复购次数/率。

评分规则：

- 使用中位数和 P90，不使用单次平均。
- 按线索来源、批次、国家等质量因素分层。
- 样本不足显示“样本不足”，不排名。
- 评分只做分配建议，不自动垄断分配。

客户 A/B/C 分级默认查询派生，人工覆盖必须保存原因、修改人和时间。分级不能替代线索状态、阶段或负责人。

## 9. 失败与幂等

- 写接口统一返回 `{ ok, data?, error? }`。
- 鉴权在副作用之前完成；失败不得创建公司、通知、任务或 outbox。
- 终态幂等重放返回同一回执；未知传输结果使用同一幂等键重试。
- 确认写入后必须失效对应查询和本地镜像；批量导入按批事务，不能逐条全库扫描。
- 中心权威数据不得被旧本地镜像覆盖。镜像损坏或未就绪时，必须回退中心读取或返回明确失败，不能伪装成空列表。
