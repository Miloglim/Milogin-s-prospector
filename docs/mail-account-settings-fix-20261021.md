# 发信账号配置纠偏

## 目标

撤销登录后自动生成发信账号，修复既有账号无法可靠编辑保存的问题。中心身份、邮箱授权码和服务商服务器必须分别由明确来源提供，不根据登录邮箱猜测。

## 已实现

- `ProductLogin` 登录成功后不再调用 `accounts:upsert`；中心密码不再写入本地邮箱账号。
- 编辑账号时可实际修改邮箱地址、SMTP/IMAP、端口、显示名和签名；邮箱在本机发信账号中必须唯一。
- 密码留空继续保留原密文；填写新密码时才执行 SMTP/IMAP 验证并重新加密。
- 设置弹窗保存失败会显示主进程错误，不再静默关闭或无反馈。
- 表单明确标注“邮箱密码 / 授权码”，并说明它不是中心登录密码。

## 验证

- 中心登录不创建发信账号的渲染测试通过。
- 编辑既有账号、修改邮箱、服务器但密码留空的渲染交互测试通过。
- 邮箱实际更新、重复邮箱拒绝、仅发信账号和编辑免重输密码的账号服务测试通过。
- 相关定向测试共 16 项通过，`npm run typecheck` 通过。

## 边界

- 不读取或验证当前真实邮箱授权码；真实 SMTP/IMAP 验证仍需用户在编辑时填写对应服务商密码或授权码。
- 既有自动创建的账号不会被自动删除或猜测归属，用户可在设置页修正或删除无历史引用的账号。
