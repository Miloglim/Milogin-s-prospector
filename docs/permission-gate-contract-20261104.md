# 客户端权限门禁契约

## 目标

客户端权限字段只负责减少无效操作和给出提示，不替代服务端授权。权限值缺失时不得被静默解释为“明确禁止”，否则旧中心、缓存重载或字段演进会把有效账号误判为无权限。

## 三态语义

| 客户端值 | 语义 | UI 行为 |
|---|---|---|
| `true` | 明确允许 | 显示并允许发起操作 |
| `false` | 明确禁止 | 禁用或拦截，并提示原因 |
| `undefined` / 未返回 | 未知 | 不因未知禁用；允许用户发起，由服务端最终裁决并返回真实错误 |

## 适用范围

- 联系人：`canEdit`、`canDelete`、`canAssign`、`canFollowup`、`canSendMail`、`canShare`
- 公司：`canEdit`、`canDelete`
- 字段级权限：`permissions.editableFields`、`canFollowup`、`canChangeStage`

## 硬性规则

1. 禁止使用 `!canDelete`、`!canEdit` 之类写法直接判断可选权限。
2. 只有值严格等于 `false` 时才视为明确拒绝。
3. `undefined` 必须交给服务端验证，或先刷新详情后再判断。
4. 权限变化后仍沿用原请求链：服务端拒绝时显示服务端原因，不在客户端伪造成功。
5. 删除、分配、发信等服务端写接口继续校验角色、产品准入、归属、版本和依赖。

## 删除链路前置校验

- 明确禁止：分配中、非本人个人线索、非运营管理员可管理的运营线索、版本缺失等客户端已知条件。
- 未知权限：继续发送中心删除请求。
- 回执成功：移除本地列表和详情缓存。
- 回执失败：保留本地数据，显示中心错误，不做乐观删除。

## 测试要求

- 权限为 `true`：允许操作。
- 权限为 `false`：客户端拦截。
- 权限为 `undefined`：允许发送请求，服务端错误原样返回。
- 同一语义在联系人列表、详情、公司、分配和收件箱入口保持一致。
- 权限字段变更或缺失不得导致按钮无反馈、请求不发出或数据提前消失。
