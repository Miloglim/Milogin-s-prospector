# 已接受发送的迟到归档

用户批准上节点提出的“邮件已发出、回执上传前撤权时保留真实发送记录”。前端保持，安全边界为发送前登记授权、发后独立归档，绝不能把客户端声称曾有权限当作绕过当前鉴权的理由。

1. 中心先行契约 `server/core/send-acceptance.ts`：两个内部HTTP路径，发送授权输入绑定发送编号/操作者/邮箱/主题/联系人及收件地址。发送前实时复核权限和邮箱，一次授权只消费一次实际接受事实；重复相同回执幂等、换人/换邮箱/换主题/过期发生时间拒绝。新025加法表保存授权与消费关联，原邮件事件表复用。会话失效继续拒绝，恢复登录后可补传，不能绕过账号停用。
2. 独立归档返回只含eventId/duplicate/archivedAfterRevocation，无联系人资料。已有当前权限沿原事实逻辑更新；已失去线索权限只归档过去发送，不推进新负责人发送阶段或恢复联系人投影。原普通邮件POST继续实时鉴权，不开放通用绕过。
3. 客户端发送前保留原实时校权、营销止损检查，再登记授权并持久保存；SMTP接受后按真正接受子集记录。原镜像队列承载授权编号，独立归档接口只确认已发事实；断网/切换账号/重启保留原作用域和原载荷，禁止自动再次SMTP。无凭证旧blocked事件不伪造授权或自动解除。
4. 红→绿覆盖同账号/异账号、撤权后发送阻断与旧事实归档、部分接受、幂等、失效会话、冲突与回滚；完整隔离PG、生产Electron原界面及原生SQLite联调，无真实外发。最终备份并只部署本机55844，核对表字段和接口无重复，并写回文档与知识库。

Checkpoint：D:/Agent Basement/checkpoints/prospector-late-send-receipt-20261016。

实现判断：需要中心事前授权日志以避免信任本地自报历史权限；增加两个明确用途的HTTP接口，不增加用户界面或IPC，不引入依赖。SMTP接受本身仍来自现有可信桌面回执，授权日志不是邮件送达或服务器独立验证SMTP的证明。上传可晚于授权期限，但事件发生时间必须落在本次发送窗口内；超窗或结果未知不自动重发。
