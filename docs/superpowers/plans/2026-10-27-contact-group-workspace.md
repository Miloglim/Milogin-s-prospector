# Prospector 联系人群组工作台计划

日期：2026-10-27
状态：已列入计划，未开始实现

## 目标

在现有联系人一级分组页之上增加群组工作台，让管理员和用户能同时看到分组结构、组内概况和成员明细，并从同一界面完成查看、筛选和批量分配。

“群组”在这里指联系人/线索分组，不是聊天群。第一版不创建新的持久化群组类型，也不允许手工修改成员归属。

视觉参考：[Customer Journey CRM Dashboard](https://dribbble.com/shots/24659454-Customer-Journey-CRM-Dashboard)。借鉴旅程式横向分组和清晰的主次层级，不复制大圆角、玻璃质感和装饰性动效；继续遵守 Card + Carbon Tile 的平铺、轻边界、8px 圆角规则。

## 页面结构

- 顶部固定：分组维度、搜索、范围筛选、全选和批量操作。
- 左侧主区：按导入批次、国家、公司或客户类型展示紧凑分组卡片；卡片显示数量、公司数、国家数、已触达数和最近更新。
- 右侧详情区：选中分组后显示组内联系人摘要、分页成员列表和可执行操作。
- 窄窗口：详情区改为抽屉或上下堆叠，不压缩成员字段到无法阅读。

## 交互范围

- 点击分组卡片在当前工作台切换右侧详情，不立即跳离一级页。
- 支持单组查看和多组勾选；批量分配继续复用现有分配请求与组 ID 链路。
- 支持按联系人状态、负责人、国家和客户类型继续筛选组内成员。
- 空分组、读取失败、权限不足和超过 200 人上限都要在原位显示明确状态。

## 数据边界

- 分组汇总继续使用 `/api/crm/contact-groups`。
- 组内成员继续使用同一授权范围的 `/api/crm/contacts` 与 `groupDimension/groupKey`。
- 第一版不新增数据库表、IPC 或 HTTP 路由。
- 若后续需要“手工建组、跨批次归组、固定群组成员”，再单独设计持久化群组和迁移契约，不能拿现有分配组冒充联系人分组。

## 实施阶段

1. P0：只读工作台，左侧分组卡片 + 右侧成员列表。
2. P1：组内搜索、筛选、分页和详情返回位置。
3. P2：多组批量分配、跨页选择状态和操作后刷新。
4. P3：根据真实使用反馈评估持久化群组、规则分组和自动归组。

## 验收

- 桌面宽屏和最小窗口下，分组区与成员区均可用，无横向溢出和文字遮挡。
- 分组数量、成员数与现有联系人二级页一致。
- 多选分配的权限、200 人上限、幂等和通知行为与现有链路一致。
- 中心离线、权限变化和联系人列表变化时保留失败结果，不把失败伪装成空分组。

## 暂不做

- 聊天群、消息群发和群成员实时协作。
- 手工拖动成员归组或复制另一套联系人归属。
- 自动分组 AI、标签规则和群组生命周期管理。
