# 开发视角切换及超级管理员定位

2026-10-12，0.24.0-alpha.1 工作区，未发布。B3 暂停，导入简化尚未实施。

开发版登录超级管理员后，Ctrl+Alt+P 打开界面视角，可选真实身份、超级管理员、管理员、用户；预览顶部显示角色、当前账号数据及只读，退出恢复原布局。正式构建和普通账号不开放快捷键；预览不持久化，账号切换清空。

视角只投影客户工作面和底栏身份显示，不换主进程身份、凭据或中心授权。客户预览查询使用当前真实管理员获准的 all 范围，故记录仍是当前账号数据，不是另一用户的数据模拟。客户筛选布局可查看，但预览范围不代表真实角色可见性。中心若无全量读取授权会拒绝，预览不绕过权限。其他个人工作页仍为真实账号；没有尚未实现的用户目录/角色页面。

所有客户写操作，包括嵌套分表导入和分配弹窗，预览时在调用 IPC 前拒绝。实际读取仍经中心授权；没有注册模拟身份 API、修改角色、写 SQLite 或扩展 IPC。真实归属、通知、离线和权限联调继续用隔离管理员/用户账号（已有 dev:dual）。退出预览后恢复正常编辑。

## 账号职责

| 身份 | 工作职责 | 当前实际边界 |
|---|---|---|
| 用户 | 管理自有及分配客户、开发和记录跟进 | 仅获准自己的客户，个人邮件/设置依账号隔离 |
| 管理员 | 导入、分发自己的来源线索，查看对应跟进 | CRM operations 能力；不是账号中心管理身份 |
| 超级管理员 | 全量CRM审查、权限治理、账号和会话管理 | identityAdmin管理账号中心；CRM admin+有效shared准入全量查看，两项独立 |

不是“高角色包含所有低角色”。目前CRM admin不含operations的leads.import/leads.publish能力，分配还要求本人创建的未归属来源；因此超级管理员不是自动获得所有业务按钮的日常运营账号。只拿到identityAdmin也不自动获得CRM所有数据权限。后续是否调整这套能力矩阵需单独方案，不在本次调试修复中偷偷扩权。

超级管理员不代表能读所有私人邮箱密码/配置；尚未上云的邮件不代表中心已有完整副本。其监督界面和指标也并非全部落地。
