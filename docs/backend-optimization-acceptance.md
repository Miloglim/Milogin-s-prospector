## 实现、收益与代价

| 项 | 原因与实现 | 提升 | 副作用 / 限制 |
|---|---|---|---|
| A | 阶段变更只覆盖标签、详情过滤事件类型。阶段和 stage 活动同事务写入，详情补类型，最近跟进排除 stage/reminder，保留首次兜底时间。 | 可追溯阶段历史；切阶段不清零逾期，包括只有老兜底时间的客户。 | 实际切换多写一条活动；同阶段不重复写。未实施可选的提醒事件。 |
| D | 缓存失效分散且收信/发信遗漏 CRM。统一为 `cacheDeps.ts` 的映射，App 接收已有事件，写入口调用 helper。 | 保活看板收到回复、发信或删客户后刷新。 | 部分操作刷新更多查询；保留发送回调的延迟再次对账。 |
| B | 完整正文在本地 HTML 文件，不在 inbox 表。签名规则仅从当前邮件签名提取，匹配实际发件人，后台填空职位/电话/现有公司。 | 收信和正文到达后自动完善档案；成功回填 24h 内防重。 | 不标准签名会漏识别。公司未匹配/不唯一不写；不新建公司，不覆盖人工值。自动抓取复用现有 20 封正文预热，后台最多增加这批正文的网络请求，并合并并发预热。 |
| C | 无跨域检索。命名迁移建 FTS5 与写入/修改/删除触发器，旧预览回填、本地全文后台补齐，sidebar 入口分组展示并深链跳转。 | 可搜索邮件、手动跟进与联系人；Latin 词 FTS 前缀匹配，中文 LIKE。 | 数据库增加索引与原文副本；首次旧数据索引同步建立，全文回填在后台。未缓存正文只有预览；索引同步有写入成本。 |
| E | 后端 5 天与前端 3/5 天硬编码分散。现有配置增两键，服务下发阈值，前端只使用服务判定，设置成功后刷新并重算建议。 | 看板、详情、仪表盘提醒与助手的逾期查询同源。 | 修改阈值立即改变名单；显式提醒优先。非法值拒写、旧/损坏值回默认。 |
| F | 两索引在 `schema-sql.ts` 已存在，但 Drizzle 声明缺失。补与现有名称一致的声明。 |  schema 口径一致，保留已有索引覆盖。 | 无新业务列、无重复索引；不宣称获得原本不存在的性能提升。 |
