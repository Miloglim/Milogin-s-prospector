# 收件箱全屏布局

日期：2026-10-20  
状态：0.53.2-alpha.1 工作区已实现并完成本机验证，未发布。

## 问题与改动

此前收件箱位于 `AppLayout` 的通用滚动容器中，内容区固定增加 `16px 20px`；页面自身又使用 `calc(100vh - 130px)`，正文使用 `calc(100vh - 290px)` 估算可用高度。窗口最大化、还原或高度变化时，这些视口减法会留下底部空带、产生外层滚动或裁切正文区域。

本次仅为 `/inbox` 启用全屏内容模式：移除通用内容留白和外层滚动，让收件箱直接占用标题栏下方的完整工作区。收件箱根容器、左右栏和正文容器改为由 flex 分配剩余高度，并补齐 `min-height: 0` / `min-width: 0`，不再依赖固定视口减法。邮件查询、分类、选择、快捷键、右键菜单、联系人匹配和正文加载逻辑未改。

## 验证

- `tests/integration/inbox-center-renderer.test.tsx` 10 项通过，覆盖中心联系人匹配、正文加载、分类结果、状态/阶段权限和原交互边界。
- `tests/integration/app-layout-fullscreen.test.tsx` 2 项通过：`/inbox` 移除通用 padding 和外层滚动，其他路由继续使用原滚动容器。
- `tests/unit/inbox-full-screen-layout.test.ts` 2 项通过：锁定边到边路由类与收件箱内部可滚动容器约束。
- `npm.cmd run typecheck`、`npm.cmd run test:architecture`、`npm.cmd run build` 通过；构建仅有既有 `system.ipc.ts` 动态/静态导入分块提示。
- 真实 Electron：还原窗口 `1280×800` 时内容区为 `1070×764`，收件箱左右栏同高；最大化到 `1920×1032` 时内容区为 `1710×996`，页面、左右栏底边均与窗口底边一致，内容区内边距为 0，无页面级多余滚动。
- 当前本机账号收件箱为空，实机覆盖左右栏和空状态；有邮件时的正文态由既有集成测试覆盖，未向真实邮箱拉取或产生测试邮件。
